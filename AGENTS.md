# HeLab Agent Notes

HeLab (Helium Experiment Lab Analysis Board) is a PyQt6 desktop GUI application for real-time scientific data analysis in the ANU Helium BEC lab. It monitors experiment data folders, runs pluggable analysis scripts, and renders interactive visualizations.

Two repos exist: this one (`TonyXTYan/HeLab`) is the development branch; `HeBECANU/HeLab` is the stable lab deployment.

## Working conventions

- Address the user as "🎓Tony" in conversation.
- Always ask Tony before running `git commit` in his checkout or on his branches. Staging, diffing and reviewing are fine without asking. An agent working in its own worktree, Maestri floor or cloud environment, on a new branch started from the commit Tony or the coordinator chose, may commit there freely and pushes that branch once, when its work is done (to save CI runs); merging into Tony's branches, landing a floor and opening a PR still need his approval ([agent workflow](roadmaps/agent-workflow.md)).
- Every Git commit must include both a concise subject and a meaningful description in the message body, separated by a blank line. The description should explain what changed and why, and include relevant validation.
- Whenever possible (a task finished, a natural pause, or work that touches the same area), offer to take on open items from `roadmaps/_readme.md` that fit, saying which and why. Offer only; start one after Tony agrees.
- CodeGraph (`codegraph_*` tools, `.cursor/rules/codegraph.mdc`) is reliable for definitions, signatures and source, but its callers, callees, trace and impact results miss many calls made through attributes (e.g. `self.model.cache.submit(...)` reaching `FolderCache.submit`). Confirm them with grep before relying on them.

## Setup

Python 3.13 is the required version (CI gates on it). Use uv, as the README's "Setup (any machine)" guide does:

```bash
uv python install 3.13
uv venv --seed --python 3.13 venv && source venv/bin/activate   # Windows: venv\Scripts\activate
uv pip install -r requirements.lock -e .   # pinned; requirements.txt lists direct deps (README: refreshing the lock)
git submodule update --init --recursive   # legacy/tdc_autoconverter
```

`venv/` may be a symlink to `venv.nosync/` (keeps it out of iCloud Drive sync on macOS) — both names are gitignored and activation/imports behave identically either way.

## Running

```bash
helab              # via entry point
python -m helab    # via module
```

Each HeLab logs to its own `<app folder>/logs/helab-<pid>.log` (INFO and up, rotated at 2 MB, 4 older files; macOS `~/Library/Caches/HeLab/logs/`, Windows `%LOCALAPPDATA%\HeLab\logs\`). An unhandled exception, on any thread, is logged with its traceback and HeLab carries on, with a status-bar note "Unexpected error, logged: …"; the same one is logged at most once a minute, its repeats counted (`helab/utils/app_log.py`, started first in `main()`). A source file dated more than 2 s ahead of this PC's clock makes helpers send `clock_skew`: HeLab says the computers' clocks are out of sync, once per share or volume per session (`ClockSkewWarning`), and Live on that folder stops like an error stop. Nothing deletes old sessions' files.

## Testing

```bash
pytest                        # all tests
pytest -n 12 --reruns 5 --reruns-delay 1 --verbose   # faster: parallel, retries flaky tests
pytest tests/test_foo.py      # single file
pytest --cov=helab            # with coverage
```

For the full suite, prefer the parallel form: `-n 12` runs 12 pytest-xdist workers (use at most the machine's CPU cores; CI uses `-n 4`). Never use `-n` without `--reruns` and `--reruns-delay` (pytest-rerunfailures): parallel workers can race (e.g. over temp folders) and Qt/timing tests fail now and then under load. Report any test that needed a `RERUN` rather than calling the run clean. Tests run Qt offscreen by default; set `HELAB_SHOW_GUI=1` to see the windows. `tests/conftest.py` gives every test's `tmp_path` a `.helab-root` and a fake volume ID (`temporary_data_root`); tests of RAM-only folders or of markers themselves opt out with `@pytest.mark.no_auto_data_root`. **Tests never touch real data** (Tony, 2026-10-20): conftest sets `HELAB_TEST_SOURCE_GUARD`, under which the helper (`helab/io_ops/infra.py`, `_guard`) refuses (`SourceRefused`, before touching it) any source path below `/Volumes`, `/Network`, `/net`, `/media`, `/mnt`, `/run/media` or `~/Library/CloudStorage`, a network or other-drive path on Windows, or inside `constants.DEV_POTENTIAL_DATA_PATHS`, unless it is inside the temp folder or this checkout; the refusal fails the test (`no_real_data`, `tests/test_real_data_guard.py`), and new tabs start in an empty temp folder. A test of mounts uses paths that don't exist. Production code reads these test seams: `HELAB_TEST_LOCAL_MOUNT` (Windows: one local mount), `HELAB_TEST_VOLUME_ID` (a fixed volume ID) and `HELAB_TEST_READ_GATE=<dir>` (`helab/io_ops/infra.py` only: a TXY read of `<name>` waits until `<dir>/<name>.go` exists, sending nothing meanwhile, so tests order reads on every platform and a gate never opened is a stuck read; `tests/test_live_io.py`) and `HELAB_TEST_IO_TRACE=<folder>` (`helab/io_ops/infra.py` only: every helper appends each source-folder operation to its own `<folder>/<pid>.jsonl`, as Help › Record I/O trace does; `tests/test_io_trace.py`) and `HELAB_TEST_SETTINGS_FILE=<file.ini>` (`helab/utils/settings_store.py`: `app_settings()` opens that ini instead of the native store; `tests/conftest.py` gives every test its own). `tests/conftest.py` points the cache, temp and app folders at private temp folders (`HELAB_DIR_*_OVERRIDE`, `HELAB_APP_DIR_OVERRIDE`), which `helab.utils.constants` reads once at import: never import helab before pytest loads conftest (e.g. a script calling `pytest.main()` after its own helab imports; patch from a fixture instead). Conftest refuses to run then, since tests would write into the real cache. A script that imports helab outside pytest (a render or debug script) should set those three variables first too.

`pytest.ini` sets `pythonpath = .`, so pytest tests the checkout it runs in, whatever the venv's editable install or `PYTHONPATH` names (`tests/test_test_isolation.py`). Each test gets a disk cache store of its own (`private_store` in `tests/conftest.py`: `cache_dir()` and the helpers' `HELAB_DIR_CACHES_OVERRIDE`), so nothing a test saves reaches another. Deferred deletes are sent after every test, also when its teardown raises, and a test that leaves a `QWebEngineView` alive fails (one deleted later crashed Qt; `tests/test_left_widgets.py`). The summary prints "rerun reasons" (why each rerun failed): quote them when reporting a RERUN. In CI logs, rerunfailures sleeps `--reruns-delay` before it logs RERUN, so subtract it (5 s on CI) from a rerun's apparent duration.

Windows: if pytest crashes during cleanup with `WinError 5` for
`pytest-current`, use either option in PowerShell:

```powershell
pytest --basetemp="$env:TEMP/helab-pytest-fresh"
pytest --basetemp=.ai/temp/pytest-fresh
```

Use a dedicated scratch directory per concurrent run: pytest clears it at startup.
See [investigation notes](.ai/sessions/2026-10-13-codex-windows-pytest/notes.md)
for details and a separate intermittent cache-move failure.

Tests ending in `.disabled` are intentionally skipped (not collected) — don't try to "fix" them into passing without checking why they were disabled first.

## Type checking

Strict typing is enforced — everything should be typed.

```bash

```

`tests/test_typing.py` runs these (plus non-strict mypy) inside `pytest`, so type errors in tests fail the suite. ## Architecture

**Package layout:** `helab/models/`, `helab/views/` (the plot UI in `helab/views/plots/`), `helab/workers/`, `helab/scripts/`, `helab/utils/`

**Responsive filesystem I/O:** The active folder browser uses `IOService` (`helab/utils/io_service.py`) and isolated `helab/io_helper.py` processes: that module is the process entry and dispatcher, each operation family a module of `helab/io_ops/` (browse, scanning, loading, save_held, live, icons, markers, admin, trace_check) over shared infrastructure (`infra`: tracing, traced calls, test seams, `Pause`, `Heartbeat`; `stores`, `fingerprints`, `metadata`, `summary`, `identity`). Nothing in `helab/io_ops/` imports `helab.io_helper` (it runs as `__main__`), and tests patch a name in the module that defines it. A name tests patch must be called as `module.name` from other modules, never imported by value (today `stores._cache_store`, `infra._volume_id_cache`, `infra._read_txy_file`, `fingerprints._raw_mtime`, `metadata._send_saved`, `markers._discover_root`); names patched and read only in their own module (`fingerprints.SETTLE_SECONDS`, `scanning._scan`, `browse._mount_fingerprint`, the trace globals in `infra`) stay bare there. The helper's events are a typed contract in `helab/io_ops/events.py` (a `TypedDict` per event shape, their union `HelperEvent` and `KINDS`; standard library only, so the app can import it): `Emit` accepts only those, so strict mypy checks every event's fields where it is sent, and `tests/test_helper_events.py` checks the kinds the helper sends and the app matches on against it. Requests are deduplicated, queues and concurrency are bounded, and cancellation/deadlines never wait on the GUI thread. Daemon reader threads deliver results through a bounded queue; a Qt timer applies small batches. A helper's stderr goes to `stderr.txt` in its private folder; when it exits without `done` or `error`, the last 2 KB are logged with the operation and path. Writing a Live save's held arrays to that folder counts as progress for the no-progress timer. Source folders are never queried by the GUI model. The frozen helper entry point in `helab/main.py` must run before imports that initialize GUI services, caches, or Dash. `GUIWatchdog` records event-loop stalls and dumps thread stacks independently of GUI timers.

Rules for the shared I/O queue (decisions, timings and the stopping-helper display: `.ai/memory/results/folder-io-queue.md`):
- One app-wide queue with two source-I/O lanes. The **foreground** lane runs the current tab's listings (`list`, `resolve`) and its selected load (in queue mode, its queued loads one at a time): one listing and one load at once, at most 3 processes including stopping ones, and it never waits for background work. The **background** lanes (Settings → General, "Simultaneous background I/O operations", default 1) run everything else: background loads, `details`, basic scans, cache writes and history saves. Navigation and loads precede bulk scans; FIFO within each group. A tab's Live checks run in its foreground lane but pause background work only while they read a file. `FolderCache` decides the lane (`foreground_owners`, set by the current `FolderExplorer`); switching tabs makes the old tab's work background.
- While the foreground works, background loads and scans **pause cooperatively** (a `pause` file in the helper's private folder, checked between files/entries; `paused`/`resumed` events) and no new ones start; the selected load pauses while the tab lists a folder. Resume is 0.5 s after the foreground goes idle; a listing silent for 3 s no longer counts. A paused helper keeps its slot and its no-progress timer is frozen. A load leaving the foreground takes a free background slot, or is stopped and requeued to restart from its RAM shots.
- **Automatic loads wait for the selection to settle** in Finish and Cancel modes (Queue mode keeps its 3 s wait): while a load is running, queued or stopping, or one started under 0.3 s ago, an automatic load starts only once the selection has stayed for 0.3 s plus 0.1 s per queued I/O task other than the folder's own, at most 1 s (`FolderExplorer.settle_seconds`); when idle it starts at once. Data in RAM shows at once; the cached read and the check wait. Tests set `SETTLE_MAX = 0` (`tests/conftest.py`).
- A third, **local** lane (2 processes) runs `cached` reads of the local disk cache, batched `subtree_save` writes of derived subfolder status, `cache_admin` maintenance (the startup sweep) and `volumes_verify` (mounted volumes' IDs only, for data-root hints) and `trace_check` (before Help › Record I/O trace starts: the temp folder's network/synced check and its earlier recordings; 10 s no-progress timeout). They never touch source folders, never wait for or pause with foreground/background work, and are never paused. The user's `root_create`, `root_reassign` and `root_remove` (one marker write each) run in the foreground like a listing.
- **Cache first.** Selecting a folder with a disk cache shows its data at once (memory, else a `cached` read), marked unchecked (`loaded (cached)` / `Checking for changes…`). The check is a load that runs **beside** the cached read (`cache_base`: it counts the cached shots as held; `FolderCache` holds its result until the read's dataset arrives; a failed or too-large read cancels it, and a plain load follows). Leaving the folder cancels a check that hasn't found files to read together with its read; one reading new files moves to the background with its read (Finish, Queue), and they stop together. Data in RAM counts as checked only for `FRESH_SECONDS`, after a load checked it or a scan of the folder found the same files (`FolderCache.counts_as_checked`, the one rule for the tab's label and for answering a load from memory; cached data counts only by such a scan), so returning to a folder later checks it again. When the cache has no unsettled files and the folder's mtime is exactly the one stat'ed just before the cache's listing (`info["folder_mtime_ns"]`, compared only with itself since it is the server's clock; None, so the next check lists, when within `RACY_SECONDS` = 2 s of the listing and after a Live save; caches without it compare with `snapshot_at`; `memory_check` carries the same value; `fingerprints._mtime_unchanged`), the helper answers `unchanged` without listing, after statting a sample of the cached TXY files (Settings → General → Check of cached data: Swift = last, Fast = first and last, Medium (default) = those plus max(3, 1%) random, High = plus max(10, 3%), Full = always list; names saved in the dataset info). A full listing that finds every cached TXY file unchanged, none still being written, records that without rewriting the dataset (`CacheStore.confirm_dataset`): `snapshot_at` moves to when it started, `unsettled` to 0, and older caches gain their names, so a later non-TXY change (Finder's `.DS_Store`) doesn't rule out the quick check for good. Otherwise it lists, fingerprints and merges as usual. Shots cached or held that the folder no longer lists stop the load before any file is read (`shots_missing`): TXY files are written once, so another folder may sit at that path; a folder status check or details scan finds the same from the dataset's record alone (`cache_mismatch`, no data read). The folder's data is dropped from RAM and not shown (`FolderCache.mismatched`: session-only, up to 8192 folders, oldest dropped first; never a load's base) until a load completes or its cached data is cleared. The tab's line says Retry after checking the drive (remounting the right one is a fix) and offers Review…, which opens the window with that folder selected. One app-wide, non-modal `MissingShotsWindow` lists them (newest first; status-bar "⚠ N mismatched" reopens it) with Load as it is now (`FolderExplorer.load_as_it_is_now` → `allow_missing`, used once) / Don't load. When the session's count reaches 2, 4, 8…, loads and scans pause and none start (`IOService.mismatch_hold`, `MISMATCH_HELD`; browsing, cached reads, cache saves and icons go on) until Resume or Cancel all loads and scans; from 8, Skip mismatched folders lists them silently for the session with no more holds. Selecting a folder with saved counts and a disk cache does not list it (expanding still does). A failed check keeps the cached data with `Check failed` and Retry. A repaired TXY file gets a new name; right-click Retry / Refresh makes the folder's next check (at once for the shown folder) compare every file's size and mtime (`full_check`), since a file rewritten in place doesn't change the folder's mtime.
- **I/O trace:** Help › Record I/O trace (this session), off at every start and never saved, records every helper's source-folder operations as JSON lines in a new recording folder `<temp folder>/io-traces/io-trace-<date>-<time>/`, one `<pid>.jsonl` per helper (Windows' C runtime emulates O_APPEND, so helpers never share a file; `IOService.trace_dir`, sent with each request); refused when the temp folder is on a network or synced folder; one INFO line when it starts and one when it stops (also on quit); a status-bar note while on; Help › Show I/O trace folder; earlier recordings are kept unless the user picks Delete old traces when asked. Summarise with `.ai/sessions/2026-10-19-claude-smb-io-audit/trace_summary.py`, compare with `compare_traces.py`. Data-root verification is asked only by a listing's new mount table (one follow-up, never self-requeued, 5 s backstop); a load's fingerprint comes from its listing; RAM-held data without a disk cache gets a quick check (`memory_check`); selecting a RAM-held leaf folder doesn't list it.
- **Files still being written** (modified within `SETTLE_SECONDS` = 5 s, with an mtime ahead of this PC's clock (Tony, 2026-10-22), or changing while read) are never read or cached: they are left out of fingerprints and signatures (loads and scans alike), counted as `still being written`, and the cache records `unsettled` so the next check is a full one. Tests set `HELAB_SETTLE_SECONDS=0`.
- **Shot times** (DLD D7): a shot's time is its raw `d<N>.txt` file's mtime (Tony, 2026-10-20: raw files are never rewritten; a TXY's mtime is when it was converted). A load's, Live check's or Live save's own listing keeps the raw entries and stats one (reasons `load: shot time`, `live: shot time`, `save: shot time`; free on Windows, where the listing has the stat) only for a shot whose time isn't known: never for shots cached or held in RAM with a time (`FolderCache` sends held shots' times as `memory_raw_times` with `memory`, and as `held_raw_times` with Live's save), never in quick checks or cached reads. A known time is kept only while the shot's TXY fingerprint is unchanged (a run copied over the folder gets its own times), and a raw file modified within `SETTLE_SECONDS` gives no time yet (`io_ops.fingerprints._raw_mtime`). Raw files never enter fingerprints, signatures or reuse; a deleted raw file keeps the shot and its time. Without a raw time a shot's time is its TXY fingerprint's mtime, flagged (`DatasetView.shot_time` / `shot_times` / `fallback_times`).
- A helper occupies its slot **until its exit is confirmed** by the daemon reaper's in-memory exit flag — including cancelled/timed-out helpers and background cache writers. Never free a slot on message delivery or reader completion; duplicate exit notifications are matched by request identity.
- Browsing is two steps. `list` (one scandir, names only; the only stat is its own `.helab-root`'s, for data roots) gives counts and status at once, plus each subfolder's saved summary, history and cache flags from the local cache — so saved badges appear immediately and automatic visible scans don't redo them. `details` (the full scan) follows in the background for the signature and dates; subfolder dates come from the listing's entries (`_entry_stat(..., follow_symlinks=False)`: no call per subfolder on Windows). Saved status is a last-known result keyed by data root (root UUID and relative path; the SMB share is only a location) on disk, and by source path in session memory: a changed observed folder mtime adds the amber clock, and only that folder's own completed status check replaces its result. A status check or details scan that finds a folder's signature changed drops its datasets (`FolderCache._folder_changed`) but leaves its running load, Live check and cached read; only a clear (`_invalidate_data`) cancels them. Inodes and mount device numbers never invalidate saved status or scan-failure history. It is skipped while a load of a folder **without subfolders** runs — the load sends and saves the same folder summary. A listing writes only root-discovery records (`roots`, `root_volumes`, a nested root's re-key) and never clears a scan failure; a listing error records one. An empty `signature` means unknown, never "changed".
- Timeouts measure **time without progress**; helpers send heartbeats while listing or checking files. Listings, scans and a load's listing phase get one 60 s attempt with no retry (a timeout is one scan failure). Only a load's per-file reads retry, with 15/20/30 s attempts per file. Right-click Retry / Refresh and the status-line Retry list one folder with no timeout, showing elapsed time and a Cancel action; a load retry keeps its per-file timeouts. **A retry never runs beside the attempt it replaces** — it is held until that helper exits. Cancellation stops retries. Timed-out loads restart from completed RAM shots after fingerprint validation.

**Folder icons:** The name column starts with a generic folder icon. Visible rows get native folder/volume icons (including macOS custom icons) from a separate `icons` helper in the shared background I/O lane, in batches of at most 64 with a 5-second no-progress timeout and cooperative pausing. `FolderCache` holds up to 4096 icons in session memory, shared across tabs; failed lookups retain the generic icon until Refresh. Icon lookup never runs during listing or model rendering. Refresh clears visible icons for another lookup. Keep the native Qt platform plugin in the helper; offscreen Qt cannot supply macOS custom icons.

**Data roots:** Disk caching needs a **data root**: a folder holding a hidden `.helab-root` JSON marker (`helab/utils/data_roots.py`: `{"helab": "root", "version": 1, "uuid", "label", "created_at"}`; unknown fields are ignored, an invalid marker is no root). A folder's cache key is `root://<uuid>/<relative>` from the nearest marker at or above it; nested markers are allowed. **Without one the folder uses RAM only**: nothing is read from or written to the store for it, with no fallback to path keys. Folder details then says "RAM only · no .helab-root found here or above", but only when a helper reported it (`FolderCache.no_root`), never because a root is unknown. The store's `roots` table maps **location** keys to UUIDs (`helab/utils/cache_paths.py`): `smb://server/share/relative` for shares (server and share lowercased, SMB account omitted, `/Volumes` suffixes ignored; Windows mapped drives and UNC paths alike) and `vol://<OS volume ID>/relative` for local volumes, so two same-named USB disks never share a location. Matching is case-insensitive on SMB and Windows volumes, but keys keep the source path's spelling.
- **Discovery:** with the disk cache on, a listing lstats its own folder's `.helab-root` before its scandir, then reads and reconciles the marker (`_discover_root`: `root_found`, `root_changed`, `root_duplicate`). A marker found below an outer root re-keys that subtree's rows in one transaction (newer wins). A replaced marker starts fresh. An unreadable marker keeps the row; an invalid one forgets it and, like a removed one, sends `root_changed` (reason `marker invalid`), so tabs drop the root. If the folder's key changed, the entries are sent again with `replace`. Results (list and scan status, cached and load `loaded`) carry `data_root`, so tabs know a folder's root without listing the root folder.
- **Local lane:** it uses only the `roots` table and the `root_volumes` hints that source helpers record. Cached reads, subtree saves and scan-history writes trust only the hints this session's verification checked (`verified_volumes`, from the local-lane `volumes_verify` at startup and after a mount change), plus the system volume's. On any other volume they wait (`VolumeUnverified`) and the cached read is retried on `volumesVerified`. `roots_verify` (background, after other background work queued later: nothing waits for it) re-reads known markers. A listing asks for both again only when it reports a mount table they weren't asked for.
- **Placing one:** right-click › **Place .helab-root here…**, or **File › Place .helab-root…** for the current tab's selected folder (at first its top folder, which isn't a tree row, e.g. a drive's top; `HelabMainWindow.update_place_root_action` on `aboutToShow`), runs `root_create` in the foreground. It writes the marker with exclusive create (hidden: dot name, Windows hidden attribute, macOS `UF_HIDDEN`). It first checks for a folder that isn't the top of its drive or share, is inside another root, is a home folder, the startup disk's top (`/`, never offered) or `/Volumes` (`DataRootDialogs.placement_checks`); with warnings, Cancel is the default button. Markers go as high as every machine sees the data: Windows `C:\` is a drive top like any other (a note says it may need admin rights). An existing marker is adopted; an invalid one is never overwritten. Without write permission, `ManualMarkerDialog` hands out the exact JSON (Copy, or Save to folder… writes `.helab-root` under its exact name through the `marker_save` helper, in the foreground like `root_create`, and says how to show hidden files). RAM-only folders grey out Don't cache / Don't auto-load and Clear loaded data cache. Root folders show the ANCHOR badge beside their status icon.
- **Duplicates:** the same UUID at a new location is pending, and RAM only, until the user answers in `RootDuplicatesWindow`. It opens once per location per session: Later asks again at the next sighting, Remind me next session not until the next session, and the status bar shows "⚓ N to confirm". **Same folder** runs `cache_admin root_same`. **It's a copy…** runs `root_reassign` in the foreground: the other side gets a new marker, and the side keeping the original UUID keeps the data. Until then the tree warns on that folder and its shown descendants (ROOT_PENDING, an amber alert triangle beside the status icon, from `FolderCache.pending_root`; rows refresh on `rootDuplicatesChanged`), the row tooltip says "Data root “label” also seen at <other>: same folder or a copy? RAM only until answered.", the summary's cache line says "RAM only · this .helab-root is also at another location" with a Review… button, and Settings → Data roots has Review… on pending rows; all open the window at that location (`HelabMainWindow.review_root`, modal when Settings is open). Same folder, It's a copy… and a forgotten or removed location (`root_changed` with its location) settle it. A pending location whose other locations have all been forgotten is confirmed by its next listing.
- **Settings → Data roots** (`helab/views/DataRootsTab.py`) lists the locations and forgets one (`forget_root`). A forgotten location is found again while its marker is there. Clear all never touches `roots`. A row's menu also has Show in Finder / File Explorer / File Manager (reveals the hidden marker; a detached launch, no source I/O in the GUI) and Copy path; **Delete .helab-root…** (also a footer button; Cancel default) runs `root_remove` in the foreground: it deletes the marker only if it is still a regular file holding the row's UUID, then forgets that location and those below it with the UUID (cached data stays under the UUID), or without permission names the file (`root_remove_refused`). Open tabs list that folder, and their top and selected folders inside it, again (`rootDecided`). Not-mounted rows can't be shown or deleted. **Clear cached data…** (button and menu item, any row, mounted or not; the list's Cached column and the confirmation give the size from the inventory's `cached`) runs `cache_admin clear_root`: every record, dataset and pending save keyed below `root://<uuid>` goes in one transaction, with that root's epoch bumped (`folder_epochs` row `root-clear://<uuid>`, which every save guard below the root checks) so a save already running can't bring data back; `roots`, folder flags and the marker stay, dataset files are retired, and `removed` resets RAM flags. The user's marker writes (`root_create`, `root_reassign`, `root_remove`, `marker_save`) run in the foreground whoever asked (`MARKER_OPERATIONS`).
- **Unsupported mounts:** NFS, AFP and WebDAV mounts stay unsupported for disk caching ("Disk cache off" line per mount per session; Windows WebDAV UNC paths included). Two SMB accounts on one share use the same rows.
- **Fresh store:** the store is `store-v3`, which started empty; `store-v2` is left on disk unused, and can be moved to the Trash by hand.
- **Network plan:** the root UUID is the planned cross-machine logical root ID; location keys stay local (`roadmaps/network-runners-and-web.md`). Design: `roadmaps/data-roots.md`.

Session-only `FolderCache` and open tabs still use source paths. If shares remount while HeLab stays open and macOS reorders `/Volumes` suffixes, toolbar Refresh relists the shown branches and, when saved records can be read, replaces their RAM status, failure history and derived status with the newly mounted share's saved results. It leaves RAM datasets available but unchecked, so the next selection checks them. A background details pass re-observes folder dates for freshness hints. Restart HeLab to refresh other paths and other tabs' loaded data. A load checks TXY files and reports mismatched folders when files have disappeared, but a stale derived subfolder status can be saved under the newly mounted share and show an amber clock until its children are checked. Live tab rebinding and offline roots are future roadmap work.

**Threading:** The GUI process has no worker pools, except the single analysis worker thread (`AnalysisRunner`), which computes analyses and never does source I/O. Source-folder and disk-cache work runs in isolated `io_helper` processes, whose results daemon reader threads deliver (see Responsive filesystem I/O). `GUIWatchdog` and the Dash server run on their own background threads.

**Window resizing:** Keep Qt's normal main-window resize and repaint handling. Disabling updates for the whole window during resize and restoring them with a timer can stop paint delivery while I/O continues. Resize regressions in `tests/test_window_resize.py` check continuing paint events and scan cancellation, not just `updatesEnabled()`.

**Caching:** The disk cache is `DIR_CACHES/store-v3` (`helab/utils/cache_store.py`, `CacheStore`): SQLite records in `records.sqlite` (WAL, JSON text) and one Blosc-compressed dataset file per folder in `datasets/`. **Only helpers open it**; the GUI sends `store_options()` (`helab/utils/folder_cache.py`) with each request and never opens the store, at startup or in Settings. Reads answer found / missing / error, and an error is never "nothing saved". Every write checks a save guard taken when its job started (per-kind generations, the folder's epoch, and for datasets a `job_seq`), so a save that was already running can't bring back removed data or overwrite newer data. Replaced dataset files are retired, never deleted at once; a `cache_admin sweep` helper on the local lane deletes them later (at startup, then by the deadline each helper reports, via one `FolderCache` timer), and at startup also deletes the old diskcache folders (`data_ram_cache`, `status_cache`, `os_file_system_cache`). **Nothing is removed without the user asking.** Maintenance goes through `FolderCache.cache_admin(action, …)` (`inventory`, `clear`, `purge`, `trim`, `adopt`, `discard`, `sweep`, `forget_root`, `root_same`, `clear_root`; results on `cacheAdminResult`). Every removal sends `removed` (kinds, paths); `FolderCache.removed()` resets exactly those flags and saved results in memory, and ignores results read before the removal. A load's save checks the disk budget (`store_options()["budget"]`, default 8 GiB, live data only) in its save transaction, using the budget the app set last (requests carry `budget_set_at`; the store records the newest, so a load started before the user lowered it saves within the new one): one that doesn't fit, or that grows a cached folder while usage is at 80%, becomes a pending save (`cache_full` / `cache_approval`, tracked in `FolderCache.pending_saves`) until Make room (`adopt`) or Don't cache (`discard`). Helpers report the store's live usage with their results (`usage`, `usage_seq`); `FolderCache` keeps the newest by the store's write count (never by clock time). At 80% of the budget, automatic loads of folders without cached data pause (`FolderCache.auto_load_paused`, `FolderExplorer.auto_load_paused_path`; deliberate loads and cached folders still work) and `diskNearlyFull` asks once per crossing; Ignore lasts the session until usage rises another 10% of the budget. At startup an inventory restores saves still waiting from an earlier session, and the usage. `CacheDialogs` (`helab/views/CacheDialogs.py`) asks the cache's questions one at a time: Make room / Don't cache this folder now, Save update / Don't cache this update now, and the 80% warning. The Settings → Cache tab (`helab/views/CacheTab.py`) shows the inventory, clears by kind, purges by age and sets both budgets; every action asks first (`CacheTab.confirm`), and a changed disk budget is saved only after the store has recorded it (`CacheTab.apply_budget`). Large folders (`helab/utils/large_folder.py`): a load's or cached read's estimate is its TXY files' size on disk, unscaled; above the RAM budget or 10% of RAM, automatic loads never start (amber "Large folder · ~X in RAM" with **Load anyway…**) and deliberate ones ask (`LargeFolderDialog`); above 30% of RAM nothing loads. The tab decides from saved sizes before submitting (`FolderCache.large_estimate`, `FolderExplorer._large_blocked`), and helpers check again (`limits`, `allow_large`, `too_large` events). Folder flags (right-click › Don't cache / Don't auto-load this folder; store `folder_prefs`, `FolderCache.folder_prefs`) apply to one folder only, come with listings, and are never removed by Clear all, purges or making room; every dataset save checks `no_cache` in its transaction. Folder constants (right-click › Folder constants…, `FolderConstantsDialog`; store `folder_constants`, `FolderCache.folder_constant_records`) are one folder's own values like the flags: written only by helpers (`cache_admin constants`, local lane), the newest `set_at` winning in the store's transaction; nothing removes them (not Clear all, purges, making room or a root's Clear cached data…), so they need no save guard or epoch; a nested root's re-key moves them; when the root known at a folder changes UUID or goes (any event: `root_changed`, `root_found`, a result's `data_root`), RAM drops what the old root's store said for the folders it held, not those inside a nested root below, keeping this session's unsaved choices (`FolderCache._root_constants_gone`); listings send them for each subfolder and the folders above, only when set. A folder's values apply to its subfolders that don't set their own, up to its data root (`FolderCache.effective_folder_constants`; a fall time set above the folder that sets the fall distance is derived instead). A folder without a disk cache, or on a volume not verified this session (flags still trust every hint), keeps them for the session ("RAM only", `constants_session_only`) and saves them once a root is found or decided or the volume verified (`_constants_roots_moved`). While quitting, new flags and constants are refused, and `quit_saves` waits for those being written. Shot times are the `datasets.raw_times` column (`[shot, mtime_ns]`), not `info`, which listings read per subfolder: `loaded` carries `raw_times` and `shot` events `raw_mtime`, `FolderCache` merges them with the base's for unchanged shots (`dataset_raw_times`), and `confirm_dataset` fills times an older cache lacked (on a listing check, not the quick check). Tables and columns added within `store-v3` (`folder_constants`, `datasets.raw_times`) are added to older stores on every writable open (`cache_store._migrate`, once, under the write lock), never only in `SCHEMA`, which runs for a new store alone; read-only stores without them read as empty. While lab machines run mixed versions, an older HeLab's save resets a folder's `raw_times` to `[]` (refilled by the next listing check), and its re-key of a nested root leaves the subtree's constants behind. File kinds (TXY, raw `d*.txt`) are matched, counted and sized from one table, `FILE_KINDS` (`helab/utils/file_kinds.py`). Design and later sessions (large-folder warning, cache move, folder flags): `roadmaps/cache-storage-and-settings.md`.

**Live** (`roadmaps/live-monitoring.md`): the toolbar's Live watches the current tab's selected folder once its data is shown (`FolderExplorer.start_live`; `LiveController` and `LiveSession` in `helab/views/explorer_live.py`, the tab's `live_control`); the tab's tree, path bar, Deselect, Up, Refresh and Check folder status are locked, and the summary's third line shows Live's state. A check is a `load` with `live` in its payload (`io_ops.live.live_check`, owner `<tab>:live`, foreground lane): one folder stat while the folder's mtime equals the last safe one (not within `RACY_SECONDS` = 2 s, no files still being written, listed at least once a minute), else a names-only listing. On a listing, held shots are reused only if the folder's identity (nearest `.helab-root`, else its location) is the one Live's first listing found and the check level's sample of held shots keeps its (size, mtime); otherwise `shots_missing` (`reason` root or changed) stops Live and lists the folder as mismatched, except for a held shot Live itself read in the last 5 minutes (`LiveSession.read_at`, `LiveController.LIVE_REREAD_SECONDS`, sent as `recent`): when it changes, it is read again like a new file and replaces the held one (`live_reread`), by Tony's decision; the Live line and Folder details say "Shot N changed after it was read (writer paused > 5 s?): read again" for a minute, and one WARNING per shot logs its path, old and new (size, mtime) and the seconds since Live read it (within that window such a shot is guarded by the missing-file and identity checks only). While the folder's mtime is the last listing's, a check stats only pending files; the identity reads the known root's marker. A new file is read only when settled by age and unchanged since the previous check (`seen`): metadata only, by Tony's decision; its content isn't checked. A writer paused longer than the settle age is read unfinished; the converter writing to a temporary name and renaming it remains the real fix. Results: `live_unchanged`, or `loaded` with `memory_shots` (source `updated`). Checks have their own job key (`("live", path)`). The next check starts `live_interval` after one ends (Settings → General, 3 s). New shots stay in RAM; every `live_autosave_shots` (Settings → Cache, 10) and when Live stops (Live off, another folder, tab switch or close, quit) a background save writes the folder from RAM (`FolderCache.save` → `io_ops.save_held.save_held`: one listing, every held file checked by its stats, no TXY read; a recent changed shot is read again first; its summary is adopted only if not older than the folder's snapshot); a save never joins another load of the folder that isn't one, and saves of one folder never overlap (`_deferred_saves`); they obey the budget, Don't cache and pending-save rules. Errors stop the checks but keep Live and the data (amber line, Retry); nothing retries by itself. Quitting turns Live off and waits for `FolderCache.quit_saves()` (any job a subscriber asked to save, waiting saves, finished loads' `disk_cache_pending` writes, and folder flags and constants being written) in `QuitSaveDialog`, with Quit now; meanwhile no other folder work starts (`FolderCache.quitting`). Live never survives a restart. Live may start on any folder this session listed with no TXY files (it reads only the folder's own files, never its subfolders'): the tab shows data with no shots (`FolderCache.empty_dataset`, pinned), the first check lists the folder (`memory=[]`) and the line says "waiting for the first shot". Plots follow Live (L3): the main window publishes each dataset a Live tab shows to its plot area's `live_feed` (`PlotWorkspace.follow_live`; `LiveFeed`, `helab/analysis/live_feed.py`), `revise` makes it the next revision of the folder's view, and each plot of that folder reruns on the newest revision as its Live settings allow (`helab/analysis/follow.py`: `Follow`, `LivePolicy`); when Live stops (Live off, another tab, an error), plots holding shots back catch up once, at once. A load that reuses another dataset's arrays drops the folder's older datasets no tab shows (`_drop_superseded`). Events worth telling someone about (a low-count shot during Live, from Shot trends' Notify during Live; Live stopping on an error, `LiveController._live_halt`) go through `helab/utils/events.py` and nothing else (`events.notify`, GUI thread): hooks attach with `events.hub().add_hook` and get every event (`Event.shown` says whether it was shown); a desktop notification (`QSystemTrayIcon.showMessage`, else the status bar and the log) is asked per event, delivered once per key and at most once a minute per kind and folder (`RATE_SECONDS`), the held-back ones counted in the next.

Cache dirs resolve via `QSettings` (`dir_caches` / `dir_temps`) to `DIR_CACHES` / `DIR_TEMPS` in `helab/utils/constants.py`; the cache folder can change while HeLab runs, so read it with `cache_dir()` (never `DIR_CACHES`). It changes only by moving the cache (Settings → General → Change…, `helab/views/CacheMover.py`, `helab/utils/cache_move.py`): every helper that opens the cache is held (`IOService.hold_cache`), the folder is renamed or copied and verified, `dir_caches` is saved and synced before the switch (`set_cache_dir`), and a crash at any step is recovered at the next start (in a helper) from `cache-move.json` in the app folder (`app_folder()`), before any cache opens. OS file locks there (`cache.lock`, `move.lock`, `instances/<pid>.lock`; `helab/utils/cache_locks.py`) keep other HeLabs away from a move; tests set `HELAB_APP_DIR_OVERRIDE`. Defaults are persistent per-user folders (`default_app_dir`): macOS `~/Library/Caches/HeLab/{caches,temps}`, Windows `%LOCALAPPDATA%\HeLab\{caches,temps}`, else `~/.cache/HeLab`. A saved path is used only if a probe file can be written there. A cache folder on a network or synced folder (`helab/utils/cache_location.py`) is refused at startup: HeLab uses the default for that session and says why (`cache_dir_refused()`), leaving the setting for the user to change. Older `helab_<kind>_*` folders in the system temp dir (which the OS may delete) are renamed to the default on launch. Tests never touch these: `tests/conftest.py` sets `HELAB_DIR_*_OVERRIDE` to private temp folders.

The active browser additionally uses session-only `FolderCache` (`helab/utils/folder_cache.py`), shared by models using the same IOService. Completed directory snapshots have a 10-second freshness window; explicit refresh bypasses it. Shared scan/load/resolve jobs have per-tab subscriptions, so closing one tab does not cancel another's work. Datasets share read-only NumPy arrays with private dictionaries per tab; analysis code that intentionally modifies an array must call `.copy()`. The RAM budget (Settings → Cache, steps of 1/128 of RAM, default 1/8; `FolderCache.set_ram_budget`) evicts datasets no tab shows, least recently used first, while open tabs pin their current datasets. Plots count too (`helab/analysis/budget.py`, `RamBudget`; its Qt-free parts, the shares, `hollow` and `restore`, in `budget_core.py`): each plot's view, its result arrays (every result `RamResults` keeps for it) and a released plot's PNG picture, by buffer (`helab/utils/ram_buffers.py`), so arrays shared with a held dataset or another plot count once (`FolderCache.plot_bytes`); eviction keeps a dataset whose arrays plots hold anyway. From 50 % of the budget the status bar shows it; at 75 % a non-modal window lists the biggest plots and folders (once per crossing, re-armed below 70 %); above 80 % datasets no tab shows go first (`evict_to`, again after each release), then plots are released, least recently shown first (one reloaded in the last 10 s last), in two passes (first only plots that free more than their picture with every other plot staying), until under 80 % (never the shown, a running or a Live-following plot; none closed). A released plot shows its PNG picture with Reload and keeps a hollow view (its shots' numbers and fingerprints); it reloads from RAM or a local `cached` read only, never its folder, exactly the shots it drew by fingerprint, naming changed or missing ones, when it becomes the shown plot (Settings → Cache, `plot_auto_reload`, default on; not again after finding nothing until its folder's data or disk cache changes) or on Reload. Directory snapshots are bounded to 256 folders and 100,000 retained entries. This memory store supplements the compressed disk cache and **never reads disk during rendering**.

Persisted folder metadata lives in the store's record tables, separate from datasets, and is **written only by isolated helpers**: compact basic-scan summaries (`folder_summaries`: counts, per-kind `files` with TXY sizes, status, signature, scan date) and basic-scan failure history (`scan_histories`, `helab/utils/scan_history.py`). A failure is the final outcome after all attempts; cancellation, queue rejection and metadata-save errors are not failures. **Every automatic basic-scan entry point must honour the failure flag** (all go through `FolderCache.submit`, which checks the session's history first), and only a fresh successful scan clears it. A helper that can't read the saved history (the store won't open or its read fails) skips scans that aren't manual: a saved failure may be there. A folder with no disk cache (the cache off, or off by design for it: no data root, pending confirmation or an unsupported mount, `cache_skipped`) has no saved history, so its scans run with the session's history as the only guard, and its outcomes stay in RAM with no "could not be saved" note. Defaults, edge cases and display: `.ai/memory/results/basic-scan-defaults-and-failures.md`.

A folder's status shown in the tree can be **derived from its subfolders** (`something` if any listed subfolder has data; `nothing` only when the listing is complete and all were checked and empty) without changing its own `report`, which alone decides loading. Derivation reads only direct subfolders' in-memory statuses — never recursive. The result is saved in the store's `subtrees` table (via `subtree_save`) so it shows after a restart without listing the folder; listings attach each subfolder's saved result. Rules and tooltip wording: `.ai/memory/results/subfolder-derived-status.md`.

Typed numbers in settings (`UnitSpinBox`): a bare number is in the unit shown, a prefix alone applies, "." or the locale's comma, and beyond the limits the nearest limit; in a box with a fixed prefix (`fixedPrefix`: the DLD port's T/X/Y settings in ms or mm, `range_specs(…, fixed=True)`) "," only groups thousands and "." is the decimal point, whatever the locale ("20,450.5" is read, "20,5" refused). The RHI surface (a hidden QQuickWidget that keeps the window from closing and reopening when the first web view opens) is made only on macOS's own windows (`HelabMainWindow.needs_rhi_surface`), never offscreen. Unmaintained plotting-library prototypes are in `dev/plotting-prototypes/`, outside the package.

**DLD analyses** (`roadmaps/dld-front-panel-port.md`): **constants** come in three layers over the table in `helab/analysis/physics.py` (`CONSTANTS`: unit, source, level lab or folder, `unconfirmed`, read-only `codata`, `shown_only`, `optional` rows left unset until measured, `signed`, coded `choices`; `resolve` → a frozen, hashable `ResolvedConstants` with each value's origin and notes, e.g. a hand-set fall time more than 0.1 % from √(2h/g), which counts only at the fall distance's layer or a more specific one): Settings → Lab parameters (`helab/views/LabParametersTab.py`, `helab/utils/lab_parameters.py`, `FolderCache.lab_constants`), folder constants (Caching) and a plot's Constants group (`constant_layers.constants_specs`: "lab/folder" or "this plot" per key). An analysis declares the keys it uses (`constant_keys`, by default its Constants group's; `run_constant_keys` narrows them for a run's settings, e.g. the trap's only with a bimodal fit; `run_constants` gives None for a run that uses none). a smoothed-curve fit smooths the model too), `bec.py` and `bec_readout.py` (Tc, μ, TF radii, n0 and the QE checks from a fit), `velocity.py` (z up, v_z = ½ g τ − h/τ at release, TXY column order, never an XY rotation; m/s, ħk/m, 2ħk/m), `release.py` (release time and trap origin from one cloud; `bootstrap_release_time`; `run_velocity_source`, the one t_r and origin rule both velocity plots follow), `peaks.py`, `bootstrap.py` (`bootstrap_shots`: 1000 resamples, seed 0, 68.27 % percentile interval; `shot_means`), `spectrum.py`, `correlations.py` (g², `PairCounts` for Live; `correlate(errors="jackknife")` for errors without a bootstrap), `trends.py` (per-shot estimates, `ShotCache`, low-count rules), `masks.py` and `hotspots.py`. **Units** (Tony, 2026-10-20; `helab/analysis/display_units.py`, tick labels `plot_axes.GroupedAxis`), on axes, titles, records and settings (`ParameterSpec.unit_prefix`: shown in ms or mm, stored in s and m); frequencies, gaps between shots and other constants keep SI prefixes. **Hooks:** `result_found` becomes the result's read-only `found` (kept by a release; **Data loading:** The active browser loads TXY data in `helab/io_ops/loading.py` (in helper processes), streams per-shot results through local artifacts read by daemon threads, and retains the existing dictionary-of-float64-arrays format. It stores Blosc-compressed dictionaries as dataset files in the store, with per-shot `(size, mtime)` fingerprints, sizes and `last_used` in the `datasets` row: when a folder changes, unchanged shots are reused from the cache and only new/modified TXY files are read, then the merged dataset is written back (load source `merged`). When an open tab still holds the folder's dataset, `FolderCache` sends its per-shot fingerprints with the load (`memory`); the helper skips those shots entirely (`memory_shots`, load source `updated`), sends `loaded` first, and only then rewrites the compressed disk cache in the background (`disk_cached` event). Cache reads/writes and compression run outside the GUI process.

**Visualization:** Plotly is used for interactive 3D scatter; Matplotlib for publication-quality output. PyQtGraph draws the 2D analysis plots by default (counts per shot, the T/X/Y histograms and, in the DLD port, their fits, density images with a colour bar, mean position, T spectrum, shot times and trends on a date or shot axis, release time, velocity distributions): fast redraws for Live, and it paints on lab PCs that can't paint QtWebEngine. Every "Basic plots v1" plot can be drawn with any of the three (Drawing › Library in its settings, `helab/analysis/backends.py`: a script's `backends()` names them, default first (the DLD port's plots name none: one library, no Drawing group), and `draw(result, backend)` draws one; not a parameter, so switching redraws the shown result without a rerun and the record says "Drawn with …"). Defaults: PyQtGraph for 2D, Plotly for the 3D scatter. Basic plots v1's PyQtGraph titles are `WrappingLabel`s (`backends.set_title` for a plot's own; the DLD port's are `plot_text.WrapLabel`s): they wrap to the plot's width, since PyQtGraph's own label holds the layout at its text's full width and runs the plot off the widget's edge. Matplotlib uses `matplotlib.figure.Figure` (never `pyplot`) in `MatplotlibPane` with its toolbar. Reruns (Live's next shots) update every plot in place in every library (`update`), keeping the user's zoom and pan, else following the new data: Plotly swaps the page's figure (constant `uirevision`); PyQtGraph sets new data on the same items (auto range stays off once zoomed; drawn anew when the layout changes: log Y, the highlight or its colour, the number of orders); Matplotlib redraws onto the same figure (`MatplotlibPane.redraw`: zoomed axes keep their limits, 3D keeps its rotation, Home goes to the new data's limits, twin axes marked `FOLLOWER`); PyQtGraph's 3D view needs OpenGL (`opengl_available`, never offscreen) and otherwise says to pick another library. The 3D scatter is Plotly via the Dash server, with Open in browser (`PlotlyPane`); `DashServer.remove_plot` runs when a plot closes. The 3D scatter's page updates in place (`DashServer.update_plot`: one atomic per-plot snapshot, a 1 s poll per page, constant `layout.uirevision`), keeping the camera across reruns, in the dock and in browser tabs; a closed plot's page says so and stops polling. `DatasetAnalysis.update` lets a plot update in place. The scatter and the histograms can highlight the newest shot (`selection.newest_specs`; the histograms read its real counts on a right axis in its colour). A log axis takes `PlotDataItem`s (pen None for points): `ScatterPlotItem` ignores log mode. Avoid PyVista/VisPy (known data-point issues with large files). `helab/utils/dash_server.py` runs a background-thread Dash server (`127.0.0.1:8050`) to serve interactive Plotly figures in a browser tab via `/plot/<id>` routes.

**Legacy submodules:** `legacy/tdc_autoconverter` (git submodule from `HeBECANU/tdc_autoconverter`) is a MATLAB TDC data auto-converter kept for reference/compatibility, not part of the Python package. `legacy/Momentum_Bells_test` (`HeBECANU/Momentum_Bells_test`, branch `OneDrive-Yogesh`, ~400 MB) is the lab's MATLAB halo/momentum analysis, the reference for porting analyses such as `monitor_momentum.m` into plots. `legacy/DLD_front_panel` (`HeBECANU/DLD_front_panel`, branch `LaserMac-BECMachine-cloudstor`, ~40 MB checked out with its nested `Core_BEC_Analysis` submodules) is the lab's earlier MATLAB GUI for basic delay-line-detector data visualization and analysis; features to port: `roadmaps/dld-front-panel-port.md`.

**Settings persistence:** Uses `QSettings` with org `ANU_HE_BEC_GROUP`, app `HeLab`, opened only by `app_settings()` (`helab/utils/settings_store.py`; `tests/test_settings_store.py` fails if anything else in `helab/` constructs the native store, helpers aside, which reopen it from `settings_spec`). macOS plist: `~/Library/Preferences/com.anu-he-bec-group.HeLab.plist` (Qt derives the name from the org). Tests must not create native settings stores: `app_settings()` gives each test its own ini (`HELAB_TEST_SETTINGS_FILE`, `tests/conftest.py`), or pass a tmp-dir `QSettings(path, IniFormat)`. Lab parameters are `lab_constants/<key>` in SI units (`helab/utils/lab_parameters.py`): only values the user set (Restore removes the key, so a corrected default applies), never CODATA rows; Reset all settings clears them. `HelabMainWindow` reads them through `app_settings()`, so tests that build a real window see their own ini, never the developer's settings. Every key HeLab reads is in `helab/utils/settings_defaults.py` (key, type, default, description; the `lab_constants/` prefix; `RETIRED` keys, removed when Settings saves), and reads go through `read_setting` (`tests/test_settings_defaults.py`). Read numbers untyped: PyQt's `type=int` is 32-bit and reads 8 GiB as 0, so `read_setting` refuses typed reads of number rows.

## CI/CD

`.github/workflows/dev-cicd.yml` runs required Python 3.13 test/build matrices on
macOS, Windows and Ubuntu for every branch push and PR to `main`. A push to a
branch with an open PR to `main` runs only the detection job, since the PR's own
run tests the same commit (if the PR lookup fails, everything runs). Separate
Python 3.11, 3.12 and 3.14 compatibility matrices run only on PRs to `main`,
with soft failures. Shared steps live in `ci-test.yml` and `ci-build.yml`, with
Codecov uploads. Runs keep no artifacts: builds are uploaded (`upload`) only in a
run that releases, for the release job; test results go to Codecov only. Compatibility matrices expand on pushes, but pass `enabled: false`
to the called jobs, recording individual skips without starting runners. All
matrices disable fail-fast; required failures do not cancel
other OS tests/builds. All four matrices depend on branch/version selection;
release waits for all four, but only required matrices and version selection
must succeed (compatibility skips/failures are non-blocking). A new package
version on `main` creates an explicit tag and a draft
release; tag pushes do not
trigger releases. `python -m helab.release` validates/selects the version in CI.
`python -m helab.release_draft` validates archives and resumes draft uploads. API
errors fail selection; they never mean "no release". Only authenticated main runs
query release state. Build jobs may target an older tagged SHA during recovery;
the normal test jobs still check the current workflow commit, and recovery builds
add Python 3.13 tests of the tagged commit on each OS.
