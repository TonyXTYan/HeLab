# Codex review: Live L1 + L2

Branch `agent/live-l1`, reviewed at `f410e05` against `376c7dd` on 2026-10-19. **Verdict: changes requested.** The Live UI and queue integration are broadly consistent with the brief, but the save/quit gap and shot-integrity cases below need correction before integration.

## Findings

1. **Blocker — `helab/utils/folder_cache.py:1264-1269,982-992,1283-1288`; `helab/views/HelabMainWindow.py:1398-1402`: a joined save is invisible to Quit.** `save()` checks for a *writing* helper, then submits a load. If another tab already has an ordinary load for that path in `jobs`, `submit()` adds the Live save as a subscriber but leaves the producer payload without `save`. `quit_saves()` checks that producer payload and returns `[]` before it reaches `loaded`; closing the window shuts down the service and cancels the load/save. I reproduced this without starting helpers: ordinary `submit=True`, Live `save=True`, producer `payload.get('save') is None`, `quit_saves()==[]`. The joined producer may also carry different cache, limit, or Don't cache choices than the requested save. Track save intent separately from the producer payload, include all joined save subscribers in the quit inventory, and ensure a save request gets save semantics or runs after the ordinary load. Add a test that quits immediately after this join.

2. **Major — `helab/io_helper.py:1507,1515-1517,1533-1553,1559`: held shots are trusted across a changed folder at the same path.** A names-only listing proves only that shot numbers still exist. If an SMB share or drive is remounted to another folder with overlapping TXY names, or a previously settled TXY is rewritten in place, `set(names)-set(held)` excludes those shots. With no new names, Live reports unchanged; with new names, it merges the old arrays with the new folder's shots. `shots_missing` catches only absent names, so it cannot protect this case. The write-once rule is safe only after confirming the folder identity and that held shots still match their recorded fingerprints. Check the current data-root identity and/or file fingerprints on a listing before reusing held arrays; halt with mismatch on disagreement. Cover a replacement folder with the same shot numbers and an in-place rewrite in tests. The periodic 60 s listing bounds delayed discovery of *new names* under an unchanged SMB directory mtime, but does not detect changes to held shots as written.

3. **Major — `helab/io_helper.py:1541-1549,1575-1608`: a file can be accepted while still being written.** `_settled()` uses one candidate stat. The two `unchanged()` calls only compare size and mtime with that first result. On SMB, stale/coarse metadata, or a writer that pauses long enough for both reads while an incomplete file already has an old mtime, all three observations can agree and pandas will ingest a partial shot. The `late` path catches a change during the read, but not this case; the accepted shot then becomes trusted as held (finding 2). Recheck settlement at read time and define a completion/stability rule that tolerates the volume's metadata behavior, ideally a writer-side atomic rename or completion marker. At minimum, test a file whose metadata appears old and stable while the write is incomplete, and state the remaining real-SMB limit. The same age-of-mtime limitation exists in the ordinary loader, so a shared fix may be appropriate.

4. **Minor — `tests/test_live.py:51-77,523-534`; `tests/test_live_check.py:62-73`: tests miss the highest-risk interactions.** The Live tests replay helper events in-process and the lane test sets `current_file` by hand; these do not exercise process exit/slot retention, file timeout/retry, or the save join described above. The helper tests deliberately age folder mtimes and assert the one-stat shortcut, but never simulate unchanged/coarse SMB directory mtimes, a same-name replacement, or stale file stats. Add focused regressions for findings 1–3 and a real `IOService` test for the Live read pause/resume and retry/confirmed-exit ordering. Offscreen tests cannot establish native SMB behavior; keep the handoff's real-volume check.

## Recheck at 19bbbe0

Reviewed `git diff f410e05..19bbbe0` against findings 1–4. **Verdict: changes requested for the remaining partial-write risk; the original Quit blocker is fixed.** The worker's handoff now states the limits in findings 2 and 3, which is useful, but does not make them impossible at runtime.

1. **Finding 1 resolved.** `FolderCache.save()` now defers behind a nonsaving ordinary load, `SharedJob.saves()` counts subscriber intent, `quit_saves()` includes deferred and subscribed saves, and `cancel_for_quit()` blocks new nonsave work while it cancels existing work. Live checks use a separate `("live", path)` job key, so a save cannot join a check that may answer `live_unchanged`. The new tests cover a queued ordinary load followed by a Live save, quitting immediately, and the resulting store contents. I found no remaining version of the original quit gap in this path.

2. **Finding 2 partly resolved, with a documented limit — `helab/io_helper.py:1556-1587,1588-1604`.** A listing now checks the data-root/location identity and a sample of held fingerprints, and stops before merging on a detected mismatch. This covers the same-name replacement cases in the new tests. A fast one-stat check does not check identity, so a same-mtime remount remains undetected until the at-most-60-second listing. At the default Medium level, most held shots are not statted on that listing; an in-place rewrite outside the sample, or a copied root retaining the UUID with differences outside the sample, can still mix old arrays with new shots. This is an explicit write-once/sample trade-off in the handoff rather than a complete identity proof. Use Full checking where deterministic detection is required, or make a full held-fingerprint comparison on each Live listing before a merge. If the sampled trade-off is accepted, keep it visible as a limitation in the roadmap and real-volume checks.

3. **Major remaining — `helab/io_helper.py:1616-1626,1647-1680`: two matching observations do not prove a writer finished.** The new `seen` rule rejects a file that grows between checks; its test covers that case. An incomplete file with an old, unchanged (size, mtime) while its writer pauses for longer than one cooldown passes the age and `previous` tests, then can be parsed and held permanently. I reproduced it with a one-row partial TXY: first check reported one unsettled file, second check emitted one `shot` with one row. SMB attribute caching can produce the same observable sequence even during active writes. A completion signal such as atomic rename/marker, or an explicit decision to accept this risk, is needed before claiming Live never reads an unsettled file. The ordinary loader has the weaker age-only rule; the handoff correctly proposes a separate follow-up for it.

4. **Finding 4 substantially improved; minor test reliability concern — `tests/test_live_io.py:49-81`.** The new tests use real helpers for foreground/background pause and for three timed-out FIFO reads, and assert each retry starts after the previous helper's `exited` flag. They passed in the full suite. The pause test relies on a 3,000-file background load staying active while it creates 200 watched files and runs two checks; it never gates or asserts that the background helper is still active immediately before the reading check. On a sufficiently fast or differently loaded runner, it may finish before the expected `paused`/`resumed` events, so the test can fail for scheduling rather than behavior. Hold the background helper with a controlled test gate, or assert its active state and make the pause window deterministic. The FIFO test is POSIX-only, so this process-level retry path remains untested on Windows.
