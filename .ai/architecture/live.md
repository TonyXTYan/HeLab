Reference detail for agents working in this area. It moved here verbatim from `AGENTS.md` on
2026-10-28, when AGENTS.md was cut to rules and a map ([index](README.md)). AGENTS.md keeps the
rules every task must follow; this file keeps the mechanics, names and behaviour. Keep it true:

## Live

**Live** (`roadmaps/live-monitoring.md`): the toolbar's Live watches the current tab's selected folder once its data is shown (`FolderExplorer.start_live`; `LiveController` and `LiveSession` in `helab/views/explorer_live.py`, the tab's `live_control`); the tab's tree, path bar, Deselect, Up, Refresh and Check folder status are locked, and the summary's third line shows Live's state. A check is a `load` with `live` in its payload (`io_ops.live.live_check`, owner `<tab>:live`, foreground lane): one folder stat while the folder's mtime equals the last safe one (not within `fingerprints.RACY_SECONDS` = 2 s, the one constant the quick check and Live share, no files still being written, listed at least once a minute), else a names-only listing. On a listing, held shots are reused only if the folder's identity (nearest `.helab-root`, else its location) is the one Live's first listing found and the check level's sample of held shots keeps its (size, mtime); otherwise `shots_missing` (`reason` root or changed) stops Live and lists the folder as mismatched, except for a held shot Live itself read in the last 5 minutes (`LiveSession.read_at`, `LiveController.LIVE_REREAD_SECONDS`, sent as `recent`): when it changes, it is read again like a new file and replaces the held one (`live_reread`), by Tony's decision; the Live line and Folder details say "Shot N changed after it was read (writer paused > 5 s?): read again" for a minute, and one WARNING per shot logs its path, old and new (size, mtime) and the seconds since Live read it (within that window such a shot is guarded by the missing-file and identity checks, and every listing stats it besides the check level's sample, so a writer resuming it after a newer shot arrived is still seen: Codex review on PR #9). While the folder's mtime is the last listing's, a check stats only pending files; the identity reads the known root's marker. A new file is read only when settled by age and unchanged since the previous check (`seen`): metadata only, by Tony's decision; its content isn't checked. A writer paused longer than the settle age is read unfinished; the converter writing to a temporary name and renaming it remains the real fix. Results: `live_unchanged`, or `loaded` with `memory_shots` (source `updated`). Checks have their own job key (`("live", path)`). The next check starts `live_interval` after one ends (Settings → General, 3 s). New shots stay in RAM; every `live_autosave_shots` (Settings → Cache, 10) and when Live stops (Live off, another folder, tab switch or close, quit) a background save writes the folder from RAM (`FolderCache.save` → `io_ops.save_held.save_held`: one listing, every held file checked by its stats, no TXY read; a recent changed shot is read again first; its summary is adopted only if not older than the folder's snapshot); a save never joins another load of the folder that isn't one, and saves of one folder never overlap (`_deferred_saves`); they obey the budget, Don't cache and pending-save rules. Errors stop the checks but keep Live and the data (amber line, Retry); nothing retries by itself. A shot that can't be written for the app (`infra._save_artifact`, e.g. a full local disk) is such an error (`ArtifactWriteFailed`; in loads and saves too), never an unreadable source shot, which would be kept known and not read again (Codex review on PR #9). Quitting turns Live off and waits for `FolderCache.quit_saves()` (any job a subscriber asked to save, waiting saves, finished loads' `disk_cache_pending` writes, and folder flags and constants being written) in `QuitSaveDialog`, with Quit now; meanwhile no other folder work starts (`FolderCache.quitting`). Live never survives a restart. Live may start on any folder this session listed with no TXY files (it reads only the folder's own files, never its subfolders'): the tab shows data with no shots (`FolderCache.empty_dataset`, pinned), the first check lists the folder (`memory=[]`) and the line says "waiting for the first shot".

## Plots following Live

Plots follow Live (L3): the main window publishes each dataset a Live tab shows to its plot area's `live_feed` (`PlotWorkspace.follow_live`; `LiveFeed`, `helab/analysis/live_feed.py`), `revise` makes it the next revision of the folder's view, and each plot of that folder reruns on the newest revision as its Live settings allow (`helab/analysis/follow.py`: `Follow`, `LivePolicy`); when Live stops (Live off, another tab, an error), plots holding shots back catch up once, at once, and a following plot whose last Live run skipped work (`rerun_after_live`: a bootstrap) runs once more on it. A load that reuses another dataset's arrays drops the folder's older datasets no tab shows (`_drop_superseded`).

## Notifications

Events worth telling someone about (a low-count shot during Live, from Shot trends' Notify during Live; Live stopping on an error, `LiveController._live_halt`) go through `helab/utils/events.py` and nothing else (`events.notify`, GUI thread): hooks attach with `events.hub().add_hook` and get every event (`Event.shown` says whether it was shown); a desktop notification (`QSystemTrayIcon.showMessage`, else the status bar and the log) is asked per event, delivered once per key (once per shot), with no time limit (Tony, 2026-10-26: a shot takes about 30 s).

## Auto-convert

**Auto-convert** (TXY converter stage 4, Q6.8; `agent/txy-live`, landed `6454b4a`; `AutoConvert` in `explorer_live.py`): the Live line's Auto-convert button (shown while Live watches the selected folder; its menu: Write TXY beside the raw files… (asked first), Start Live and auto-convert here when HeLab launches, Notify below N hits…) makes each Live tick also ask for `FolderCache.convert` (owner `<tab>:live`, operation `convert`, background lane): one per folder, at least `live_interval` after the last ended, each sending the last `convert_summary`'s lists back (`seen`/`done`/`kept`/`skip`; `done`/`kept` only for the same profile). It converts with the conversion profile and backend (Settings → TXY converter). On is kept for the session per folder (`FolderCache.auto_convert`, Q9.6). A converted shot asks for Live's next check (`LiveSession.check_soon`), which reads it through the TXY source rules ([converter](converter.md)); one with fewer hits than `convert_low_hits` ([settings](settings.md)) notifies once per shot and raw file (`events.LOW_COUNTS`, `source="convert"`). A conversion's error (or Work Offline's refusal) stops auto-convert, not Live: amber line, Retry. The Live line and Folder details' Auto-convert row say converting N, converted K (last shot), waiting (no final newline, off trigger, future, unreadable) and unconvertible, reasons in the tooltip (kept across auto-convert off and on, `FolderCache.convert_reasons`).

## At launch

**At launch** (`helab/views/live_launch.py`, from the main window 10 ms in, `_open_first_tab`; Q18.3, `c718c71`): one launch folder (`live_launch_folder`, [settings](settings.md)), opened as the only tab, set to auto-convert, and Live starts once its data shows or it has no shots yet (`LaunchFolder`, as `PresetFolder`); later tabs work normally; a folder that can't be listed or started notifies once, no retry; working offline its tab opens without Live and a notification says so; never under pytest unless a test asks. Live on collapses the left panel (tabs, summary, Live line, Folder details; Q23.2) and Live off or an error restores it (a panel the user collapsed stays so). The Live line and Folder details also say "N damaged" (one notification per file, Q18.5) and "N shots with no hits" (amber, numbers in the tooltip, also for a folder shown later; A17.1, Q23.5).
