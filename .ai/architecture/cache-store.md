# The disk cache store, saved results and saved listings

Reference detail for agents working in this area. It moved here verbatim from `AGENTS.md` on
2026-10-28, when AGENTS.md was cut to rules and a map ([index](README.md)). AGENTS.md keeps the
rules every task must follow; this file keeps the mechanics, names and behaviour. Keep it true:
on Ground, update it in the same commit as the code; on a floor, propose the change in your handoff. Settled decisions and Tony's wording live in
`.ai/memory/results/`; feature plans in `roadmaps/`.

## Caching

**Caching:** The disk cache is `DIR_CACHES/store-v3` (`helab/utils/cache_store.py`, `CacheStore`): SQLite records in `records.sqlite` (WAL, JSON text) and one Blosc-compressed dataset file per folder in `datasets/` (caching v2's `store-v4`, Q19.4, [`roadmaps/caching-v2.md`](../../roadmaps/caching-v2.md), is built behind a switch that stays off until stage 2: [below](#store-v4-caching-v2-behind-the-switch); the rest of this file describes store-v3 as built). **Only helpers (and `helab convert`, a headless process without the GUI) open it**; the GUI sends `store_options()` (`helab/utils/folder_cache.py`) with each request and never opens the store, at startup or in Settings. Reads answer found / missing / error, and an error is never "nothing saved". Every write checks a save guard taken when its job started (per-kind generations, the folder's epoch, and for datasets a `job_seq`), so a save that was already running can't bring back removed data or overwrite newer data; a save whose guard names a folder re-keyed since (a nested root found) is `SaveRejected("cleared", REKEYED)` and its file retired at once, like any other rejected save (cache-5). Replaced dataset files are retired, never deleted at once; a `cache_admin sweep` helper on the local lane deletes them later (it also expires pending saves and results held over an hour, and deletes store files no row names once they are over an hour old, `_sweep_orphans`: in store-v4 the same rule covers `raw/`'s layer files, no new removal) (at startup, then by the deadline each helper reports, via one `FolderCache` timer), and at startup also deletes the old diskcache folders (`data_ram_cache`, `status_cache`, `os_file_system_cache`). **Apart from the housekeeping AGENTS.md lists, nothing is removed without the user asking.** Maintenance goes through `FolderCache.cache_admin(action, …)` (the actions are `ADMIN_ACTIONS` in `helab/io_ops/admin.py`; `clear_prefs` is Settings → Cache's Clear folder preferences; results on `cacheAdminResult`). Every removal sends `removed` (kinds, paths); `FolderCache.removed()` resets exactly those flags and saved results in memory, and ignores results read before the removal.

## Disk budget and pending saves

A load's save checks the disk budget (`store_options()["budget"]`, default 8 GB on macOS and Linux and 8 GiB on Windows (`settings_defaults.default_disk_budget`), at least 1 GB / 1 GiB, live data only) in its save transaction, using the budget the app set last (requests carry `budget_set_at`; the store records the newest, so a load started before the user lowered it saves within the new one): one that doesn't fit, or that grows a cached folder while usage is at 80%, becomes a pending save (`cache_full` / `cache_approval`, tracked in `FolderCache.pending_saves`) until Make room (`adopt`) or Don't cache (`discard`). Helpers report the store's live usage with their results (`usage`, `usage_seq`); `FolderCache` keeps the newest by the store's write count (never by clock time). At 80% of the budget, automatic loads of folders without cached data pause (`FolderCache.auto_load_paused`, `FolderExplorer.auto_load_paused_path`; deliberate loads and cached folders still work) and `diskNearlyFull` asks once per crossing; Ignore lasts the session until usage rises another 10% of the budget. At startup an inventory restores saves still waiting from an earlier session (those held less than `PENDING_MAX_AGE` = 1 h ago; the sweep expires older ones first), and the usage. `CacheDialogs` (`helab/views/CacheDialogs.py`) asks the cache's questions one at a time: Make room / Don't cache this folder now, Save update / Don't cache this update now, and the 80% warning. Byte sizes are disk or RAM (`number_format.byte_size(n, kind)`; durations name hours): disk SI on macOS/Linux and KiB/MiB/GiB on Windows, RAM in GiB everywhere (Q26.1; the platform is `number_format.PLATFORM`: `sys.platform`, or `HELAB_UNITS_PLATFORM_OVERRIDE`). Settings → Cache edits the disk budget in GB or GiB (half-unit steps) and the RAM budget in GiB; a saved budget keeps its bytes while left as shown (`CacheTab.show_disk_budget`) and goes to the half-unit grid once changed; a budget under the OS's minimum (1 GB on Windows) reads as the minimum and is saved as it on the next Save (Q32.1). The Settings → Cache tab (`helab/views/CacheTab.py`) shows the inventory, clears by kind, purges by age and sets both budgets; every action asks first (`CacheTab.confirm`), and a changed disk budget is saved only after the store has recorded it (`CacheTab.apply_budget`).

## Large folders

Large folders (`helab/utils/large_folder.py`): a load's or cached read's estimate is its TXY files' size on disk, unscaled; above the RAM budget or 10% of RAM, automatic loads never start (amber "Large folder · ~X in RAM" with **Load anyway…**) and deliberate ones ask (`LargeFolderDialog`); above 30% of RAM nothing loads. The tab decides from saved sizes before submitting (`FolderCache.large_estimate`, `FolderExplorer._large_blocked`), and helpers check again (`limits`, `allow_large`, `too_large` events).

## Folder flags

Folder flags (right-click › Don't cache / Don't auto-load this folder; store `folder_prefs`, `FolderCache.folder_prefs`) apply to one folder only, come with listings, and are never removed by Clear all, purges or making room; every dataset save checks `no_cache` in its transaction. The converter's flag (`convert_prefs`: `write_beside`, Q9.7) is a table of its own with the same rules: newest `set_at` wins, never removed by Clear all, purges or making room, turned off by Clear folder preferences, moved by a nested root's re-key; `cache_admin convert_prefs` reads or sets one (`FolderCache.write_beside`/`set_write_beside`).

## Converted TXY in the cache folder

HeLab's own TXY under the cache and temp folders (`converted-txy/`, Q27.5) aren't in the store: outside the disk budget, and nothing removes them without asking (Q12.3, Tony 2026-10-29: they get their own budget, separate from the dataset budget, built with caching v2; until then none). Settings → Cache shows their size per folder and when last used (`inventory.converted_txy`, `events.ConvertedSummaryField`, through each base's `converted-txy/index.sqlite`) and clears them when asked (`cache_admin clear_converted_txy` with the temp folder as `temps`; `removed` kind `converted_txy`; rows and old records of beside TXY stay; damaged set-aside indexes go; a newer HeLab's index is left alone; their leftover temporaries go only once over an hour old, since a younger one may be a conversion's write in progress, S0-1). Clear fences conversions already running (A19.2): it first sets a new token in the index's `fence` table, and a conversion that started before writes no TXY after it (its shots wait as `cleared` and convert at the next check); a base with no index yet, a damaged or busy index, and 0.0.7a1's Clear or conversions aren't fenced ([converter](converter.md#provenance-helabconvertprovenance)); Clear folder preferences names `write_beside`. A dataset's `info.txy` records its source and HeLab shots' origins; shots are reused only from the same kind of TXY; data of MATLAB's TXY alone is as before.

## Folder constants

Folder constants (right-click › Folder constants…, `FolderConstantsDialog`; store `folder_constants`, `FolderCache.folder_constant_records`) are one folder's own values like the flags: written only by helpers (`cache_admin constants`, local lane), the newest `set_at` winning in the store's transaction; nothing removes them (not Clear all, purges, making room or a root's Clear cached data…), so they need no save guard or epoch; a nested root's re-key moves them; when the root known at a folder changes UUID or goes (any event: `root_changed`, `root_found`, a result's `data_root`), RAM drops what the old root's store said for the folders it held, not those inside a nested root below, keeping this session's unsaved choices (`FolderCache._root_constants_gone`); listings send them for each subfolder and the folders above, only when set. A folder's values apply to its subfolders that don't set their own, up to its data root (`FolderCache.effective_folder_constants`; a fall time set above the folder that sets the fall distance is derived instead). A folder without a disk cache, or on a volume not verified this session (flags still trust every hint), keeps them for the session ("RAM only", `constants_session_only`) and saves them once a root is found or decided or the volume verified (`_constants_roots_moved`). While quitting, new flags and constants are refused, and `quit_saves` waits for those being written.

## Presets

Presets are the store's `presets` table: one row per script or arrangement preset (kind, scope, name, JSON record or NULL once deleted, `set_at`), written only by helpers (`cache_admin presets`, local lane: writes, then reads every row), the newest `set_at` winning each row in the store's transaction; a delete keeps its row so an older write can't bring the preset back. Nothing else removes them (not Clear all, purges, making room, a root's Clear cached data… or Reset all settings), and they are keyed by no folder. `FolderCache` keeps them in RAM (`presets`), read at startup and when the Presets menu, a plot's settings page or Settings → Cache › Presets… opens; RAM only while the disk cache is off or its folder refused (written by the next read once the store is there); a store that can't be read is named (`presets_note`), never "no presets". RAM follows the current store (`store_id`): a store recreated while HeLab runs is a fresh start (names unknown until it sends rows; unsaved changes kept and checked against them); a change is written only once the current store's names are known, and only to that store (a helper that opens another writes nothing); it is cleared only by the current store holding it or a later choice; a change still owed is decided in one place, once no preset work remains (`FolderCache` presets section). `quit_saves` lists Presets while a change is owed and a preset job or requested read remains; an owed change is said not saved only once neither is left. While quitting, preset changes are refused like constants.

## Shot times

Shot times are the `datasets.raw_times` column (`[shot, mtime_ns]`), not `info`, which listings read per subfolder: `loaded` carries `raw_times` and `shot` events `raw_mtime`, `FolderCache` merges them with the base's for unchanged shots (`dataset_raw_times`), and `confirm_dataset` fills times an older cache lacked (on a listing check, not the quick check).

## Tables added within store-v3

Tables and columns added within `store-v3` (`folder_constants`, `datasets.raw_times`, `presets`, `results`, `listings`, `mount_hints`, `convert_prefs`) are added to older stores on every writable open (`cache_store._migrate`, once, under the write lock), never only in `SCHEMA`, which runs for a new store alone; read-only stores without them read as empty. While lab machines run mixed versions, an older HeLab's save resets a folder's `raw_times` to `[]` (refilled by the next listing check), and its re-key of a nested root leaves the subtree's constants (0.0.5) and converter flags (0.0.6) behind, and a 0.0.6 HeLab's Clear folder preferences leaves `write_beside` on. File kinds (TXY, raw `d*.txt`) are matched, counted and sized from one table, `FILE_KINDS` (`helab/utils/file_kinds.py`). Design and later sessions (large-folder warning, cache move, folder flags): `roadmaps/cache-storage-and-settings.md`.

## Saved analysis results

**Saved analysis results** (result caching R2): a completed one-off run of a plot whose script sets `cache_supported` (Correlations, Release time) is saved in `store-v3`'s `results` table (one row per folder `root://` key and exact lookup key, a new `result_id` every save; data in `results/<uuid>.npz`, NumPy arrays and a JSON tree, never a pickle: `helab/analysis/result_codec.py`) by a local-lane helper (`result_save`), under the guard its lookup took as the run started (`gen_results`, the folder's `results:` epoch and the root's `root-results-clear://` epoch; the guard names its store). Before such a run the plot asks `result_find` (`CachedRuns`, `helab/views/plots/cached_results.py`); one refused because its folder's volume isn't verified this session waits for `volumesVerified` and is asked again once; at `VERIFY_WAIT` (15 s) the plot computes, saying "Disk cache: still checking this drive; this result isn't saved yet.", and the save waits up to `SAVE_VERIFY_WAIT` (120 s) for a guard-only lookup (a Clear after the run started fences that guard), then the amber line says "not saved: the drive couldn't be checked" (Tony, 2026-10-26). An exact match (`result_cache.lookup_key`: `reuse_key` without the folder, `found`, and Python, NumPy, SciPy and HeLab versions) shows at once and skips the run; one of the same plot and settings whose script, environment, data or constants changed shows outdated, in amber, until the run replaces it. Never Live's reruns; a folder without a disk cache, or with Don't cache, saves nothing. Results count toward the one disk budget. One that doesn't fit waits in `pending_results`, and CacheDialogs asks Make room (the least recently shown other saved results by `last_used`, never datasets, never a newer copy being saved or waiting: the plan names `result_id`s, so a copy saved after the question makes it ask again) or Discard. Clear cached analysis (Settings → Cache, and per root in Settings → Data roots) removes only results (`cache_admin clear_results` / `clear_root_results`, `removed` kind `results`) and fences saves already running. Clear all and a root's Clear cached data leave results, and presets are never removed. Purges go by `last_used`. Quitting waits for result saves and Make room (`quit_saves`); results still waiting for an answer last `PENDING_MAX_AGE` = 1 h from when they were held, like waiting dataset saves (the startup sweep expires them first); when one expires, or its store is recreated or its cached analysis cleared, the plot says why (C-2, e.g. "(expired)").

## Store identity

**Store identity** (`FolderCache.store_answer`, one rule for presets and saved results; its docstring is the full rule): answers name their store (`store_id`), and the cache folder decides which store is in use, never a clock or a counter. An answer from a store other than the one in use makes a local-lane identity probe (`cache_admin identity`) ask the cache folder. Meanwhile nothing claims anything: answers wait and are replayed in order, counts and usage count for nothing, and writes are held (`HeldWrite`; quitting waits for them, `FolderCache.cancel` ends one). The folder's store is then the store in use: a store recreated at the cache folder while HeLab runs replaces the old one's presets and results state at once, whatever order helpers answer in. A probe that fails leaves the store unknown (nothing counts, held writes and owed preset changes are said not saved, nothing retries by itself) until the next presets or result answer's probe succeeds; the same store is then a recovery. Writes (a result's guard, Make room, presets) name their store, and helpers write nothing in another.

## Saved listings

**Saved listings** (cache-only C2): a `list` helper saves each folder it lists completely below a data root, after sending its status, as the record kind `listings` (`root://` key; its subfolder names and own counts, never shot lists; `listed_at`; `gen_listings` and the folder and root epochs guard it; `helab/io_ops/listings.py`). It skips the write when unchanged and under an hour old, when a newer listing is saved (compared inside the write transaction), when the store is busy over 0.5 s, and after a failed listing. Clear by kind (Settings → Cache › Folder listings), Clear all, purges by age and a root's Clear cached data… remove them; a nested root's re-key moves them; about 450 B per folder. Online, saved listings are never read: a folder is listed when expanded, and selecting one may skip the listing ([io-and-browsing](io-and-browsing.md), cache first).

## Cache folders and moving them

Cache dirs resolve via `QSettings` (`dir_caches` / `dir_temps`) to `DIR_CACHES` / `DIR_TEMPS` in `helab/utils/constants.py`; the cache folder can change while HeLab runs, so read it with `cache_dir()` (never `DIR_CACHES`). It changes only by moving the cache (Settings → General → Change…, `helab/views/CacheMover.py`, `helab/utils/cache_move.py`): every helper that opens the cache is held (`IOService.hold_cache`), the folder is renamed or copied and verified, `dir_caches` is saved and synced before the switch (`set_cache_dir`), and a crash at any step is recovered at the next start (in a helper) from `cache-move.json` in the app folder (`app_folder()`), before any cache opens. OS file locks there (`cache.lock`, `move.lock`, `instances/<pid>.lock`; `helab/utils/cache_locks.py`) keep other HeLabs (since Q39.1, `helab convert` runs) away from a move; `running.lock` keeps one HeLab app per computer (`take_running`, taken in `main()` right after the `QApplication`, before anything opens; held for the process's life, not released at quit; a second start says so and exits 1; `helab convert` doesn't take it; Q39.1, A39.3); tests set `HELAB_APP_DIR_OVERRIDE`. Defaults are persistent per-user folders (`default_app_dir`): macOS `~/Library/Caches/HeLab/{caches,temps}`, Windows `%LOCALAPPDATA%\HeLab\{caches,temps}`, else `~/.cache/HeLab`. A saved path is used only if a probe file can be written there. A cache folder on a network or synced folder (`helab/utils/cache_location.py`) is refused at startup: HeLab uses the default for that session and says why (`cache_dir_refused()`), leaving the setting for the user to change. Older `helab_<kind>_*` folders in the system temp dir (which the OS may delete) are renamed to the default on launch. Tests never touch these: `tests/conftest.py` sets `HELAB_DIR_*_OVERRIDE` to private temp folders.

## store-v4 (caching v2, behind the switch)

Built on `agent/caching-v2` (stage 0 and checkpoint 2, landed `ad86bd3`; design: the
[addendum](../sessions/2026-10-31-claude-caching-v2/design-stage1.md)). **Off by default, and stays off
until stage 2 and Tony's go (Q28.3).**

- **The switch:** the `store_v4` settings row (bool, default off, no control). `cache_store.store_root()`
  reads it once per process (`live_layout`, through `cache_setting.store_v4_enabled(app_settings())`), so
  the GUI and `helab convert` pick `store-v3` or `store-v4`; helpers never read it and open the directory
  they are sent. `store_root_for(dir, layout)` and `layout_of(root)`: the folder's name decides (`store-v4` is
  layout 4). Off: store-v3 as above, and no `store-v4` folder is ever made (a test).
- **Tables:** every store-v3 table (`datasets` included through stage 1, Q42.3) plus `makers`, `raw_layers` and
  a `maker` column on `datasets` and `results`; `meta.format` 1 (a newer format opens read only), `gen_raw`,
  `imported_v3`, `legacy_v3` (the store-v3 choice, step 6; unset means Keep), `legacy_bytes`,
  `legacy_purged`, `forgotten_before_import`. A table added within layout 4 goes in through `store_v4.migrate`
  on every writable open, as `_migrate` does for store-v3. **Per-kind epochs** (cache-2): removing a record
  kind bumps `<kind>:<key>` (`store_v4.epoch_key`); datasets keep the folder's own row.
- **Makers** (Q28.4): one row per HeLab session (version, commit, modified, machine, environment), its id in
  each stored row. The session's maker is `HELAB_STORE_MAKER` in the environment, made at the GUI's (or `helab
  convert`'s) first `store_root()` under v4 and inherited by its helpers; its row goes in with the first data
  row. The machine id is a random UUID in `app_folder()/machine-id`. **Privacy:** the record holds the
  machine's hostname, and every `.hlb` header carries the maker's record, so a `.hlb` or saved result shared
  off the machine carries the hostname.
- **`.hlb`** (`helab/utils/hlb.py`, Qt-free, `PURE`): magic `\x89HLB\r\n\x1a\n`, a `<u4` header length (at most
  16 MiB) and the header's CRC32, a JSON header (`format` 1, `kind`, `maker`, `meta`, `arrays` with explicit
  dtypes `|i1 |u1 <i8 <f8`, codec, chunks with offset, length, size and CRC32), then Blosc chunks of at most 64 MiB
  that tile the body. Unknown header fields are ignored; a newer `format`, an unknown dtype or codec, or any
  damage is `HlbError`, never data. The raw layer's encoding: [converter](converter.md).
- **Raw layers** (step 5's store side, inert until `raw_fill`): `write_raw_file`, `start_raw_job` (`gen_raw`,
  `raw:<key>`, the root's epoch, the folder's `job_seq`), `save_raw_batch` (one transaction and fit check per
  batch; a later job's version replaces, changes in place named in `overwritten` for Q28.6; over the budget
  nothing is saved and nothing waits, Q42.1), `mark_raw_seen` (`gone_at` marks an only copy, by when its
  evidence was taken), `read_raw`, `remove_raw`; raw bytes count in the usage; `inventory()` adds `raw` and
  `older_stores` (Q28.5). Make room's order: other folders' datasets, then raw layers whose files were seen,
  then only copies, named (D8). A root's Clear takes its raw layers; Don't cache with "remove cached data"
  takes the folder's seen raw layers and keeps only copies (Q42.4); the admin's `clear_raw`, `removed` kind
  `raw`.
- **store-v3 under v4:** once v4 is live, only `LegacyStore` (`helab/utils/legacy_store.py`) opens store-v3:
  `mode=ro`, else `mode=rw` with `query_only`, `SQLITE_DBCONFIG_NO_CKPT_ON_CLOSE`; never `makedirs`, `_migrate`
  or a write (`test_only_legacy_store_ever_opens_store_v3_once_store_v4_is_live` watches every open and hashes
  v3's files). The user's state (flags, converter flags, constants, presets, roots, volume and mount hints, the
  budget) is imported once at v4's creation (Q22.4; retried while v3 can't be read; a v3 appearing later isn't
  imported; roots forgotten in v4 meanwhile stay forgotten). **Keep** (until step 6's question is answered):
  records and results are read from v4 first, then from v3 for a key v4 never removed that kind for (a
  `None` save's tombstone `legacy-hidden:<kind>:<key>`; purges by age in `meta.legacy_purged`), answered under
  v4's `store_id` with `legacy: true`; read-through only, no copy into v4 yet (A42.1). v3's live bytes count in
  v4's fit checks (`meta.legacy_bytes`, measured at each inventory). Ignore and Clear never open v3.
- **Cache moves with two stores:** `cache_move` verifies every store folder present (`store_ids_at`, the record's
  `store_ids` beside `store_id`), the live layout (sent by `CacheMover` as `layout`) is the primary
  (`primary`), `checkpoint` writes the primary only, and a v3 beside a v4 is read through `LegacyStore`. Older
  records recover as before.

## Folder metadata and scan history

Persisted folder metadata lives in the store's record tables, separate from datasets, and is **written only by isolated helpers**: compact basic-scan summaries (`folder_summaries`: counts, per-kind `files` with TXY sizes, status, signature, scan date) and basic-scan failure history (`scan_histories`, `helab/utils/scan_history.py`). A failure is the final outcome after all attempts; cancellation, queue rejection and metadata-save errors are not failures. **Every automatic basic-scan entry point must honour the failure flag** (all go through `FolderCache.submit`, which checks the session's history first), and only a fresh successful scan clears it. A helper that can't read the saved history (the store won't open or its read fails) skips scans that aren't manual: a saved failure may be there. A folder with no disk cache (the cache off, or off by design for it: no data root, pending confirmation or an unsupported mount, `cache_skipped`) has no saved history, so its scans run with the session's history as the only guard, and its outcomes stay in RAM with no "could not be saved" note. Defaults, edge cases and display: `.ai/memory/results/basic-scan-defaults-and-failures.md`.

## Derived status

A folder's status shown in the tree can be **derived from its subfolders** (`something` if any listed subfolder has data; `nothing` only when the listing is complete and all were checked and empty) without changing its own `report`, which alone decides loading. Derivation reads only direct subfolders' in-memory statuses — never recursive. The result is saved in the store's `subtrees` table (via `subtree_save`) so it shows after a restart without listing the folder; listings attach each subfolder's saved result. Rules and tooltip wording: `.ai/memory/results/subfolder-derived-status.md`.

## Data loading

**Data loading:** The active browser loads TXY data in `helab/io_ops/loading.py` (in helper processes), streams per-shot results through local artifacts read by daemon threads, and retains the existing dictionary-of-float64-arrays format. It stores Blosc-compressed dictionaries as dataset files in the store, with per-shot `(size, mtime)` fingerprints, sizes and `last_used` in the `datasets` row: when a folder changes, unchanged shots are reused from the cache and only new/modified TXY files are read, then the merged dataset is written back (load source `merged`). When an open tab still holds the folder's dataset, `FolderCache` sends its per-shot fingerprints with the load (`memory`); the helper skips those shots entirely (`memory_shots`, load source `updated`), sends `loaded` first, and only then rewrites the compressed disk cache in the background (`disk_cached` event). Cache reads/writes and compression run outside the GUI process.
