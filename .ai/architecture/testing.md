# Test harness details

Reference detail for agents working in this area. It moved here verbatim from `AGENTS.md` on
2026-10-28, when AGENTS.md was cut to rules and a map ([index](README.md)). AGENTS.md keeps the
rules every task must follow; this file keeps the mechanics, names and behaviour. Keep it true:
on Ground, update it in the same commit as the code; on a floor, propose the change in your handoff. Settled decisions and Tony's wording live in
`.ai/memory/results/`; feature plans in `roadmaps/`.

For the full suite, prefer the parallel form: `-n 12` runs 12 pytest-xdist workers (use at most the machine's CPU cores; CI uses `-n 4`). Never use `-n` without `--reruns` and `--reruns-delay` (pytest-rerunfailures): parallel workers can race (e.g. over temp folders) and Qt/timing tests fail now and then under load. Report any test that needed a `RERUN` rather than calling the run clean. Tests run Qt offscreen by default; set `HELAB_SHOW_GUI=1` to see the windows. `tests/conftest.py` gives every test's `tmp_path` a `.helab-root` and a fake volume ID (`temporary_data_root`); tests of RAM-only folders or of markers themselves opt out with `@pytest.mark.no_auto_data_root`. **Tests never touch real data** (Tony, 2026-10-20): conftest sets `HELAB_TEST_SOURCE_GUARD`, under which the helper (`helab/io_ops/infra.py`, `_guard`) refuses (`SourceRefused`, before touching it) any source path below `/Volumes`, `/Network`, `/net`, `/media`, `/mnt`, `/run/media` or `~/Library/CloudStorage`, a network or other-drive path on Windows, or inside `constants.DEV_POTENTIAL_DATA_PATHS`, unless it is inside the temp folder or this checkout; the refusal fails the test (`no_real_data`, `tests/test_real_data_guard.py`), and new tabs start in an empty temp folder. A test of mounts uses paths that don't exist. Production code reads these test seams: `HELAB_TEST_LOCAL_MOUNT` (Windows: one local mount), `HELAB_TEST_VOLUME_ID` (a fixed volume ID) and `HELAB_TEST_READ_GATE=<dir>` (`helab/io_ops/infra.py` only: a TXY read of `<name>` waits until `<dir>/<name>.go` exists, sending nothing meanwhile, so tests order reads on every platform and a gate never opened is a stuck read; `tests/test_live_io.py`) and `HELAB_TEST_IO_TRACE=<folder>` (`helab/io_ops/infra.py` only: every helper appends each source-folder operation to its own `<folder>/<pid>.jsonl`, as Help › Record I/O trace does; `tests/test_io_trace.py`) and `HELAB_REQUIRE_BACKENDS=cython,rust,…` (`tests/conftest.py`: a named converter backend that can't load stops the run, and a skip naming one fails; CI's converter-backends job sets it) and `HELAB_TEST_SETTINGS_FILE=<file.ini>` (`helab/utils/settings_store.py`: `app_settings()` opens that ini instead of the native store; `tests/conftest.py` gives every test its own). `tests/conftest.py` points the cache, temp and app folders at private temp folders (`HELAB_DIR_*_OVERRIDE`, `HELAB_APP_DIR_OVERRIDE`), which `helab.utils.constants` reads once at import: never import helab before pytest loads conftest (e.g. a script calling `pytest.main()` after its own helab imports; patch from a fixture instead). Conftest refuses to run then, since tests would write into the real cache. A script that imports helab outside pytest (a render or debug script) should set those three variables first too.

`pytest.ini` sets `pythonpath = .`, so pytest tests the checkout it runs in, whatever the venv's editable install or `PYTHONPATH` names (`tests/test_test_isolation.py`). Each test gets a disk cache store of its own (`private_store` in `tests/conftest.py`: `cache_dir()` and the helpers' `HELAB_DIR_CACHES_OVERRIDE`), so nothing a test saves reaches another. Before a test deletes a store through real helpers, it waits with `store_free(*services)` (`tests/conftest.py`) until neither its services nor the app-wide one has a cache helper running or unconfirmed. The app-wide IOService and FolderCache last a worker's run: real-window tests that change their state (Work Offline, quitting) restore it (`back_online`, `no_quitting_cache`), and a test may not assume no other service starts work during it. `tests/test_helper_events.py` reads the helper's side (`helab/io_ops/`, `io_helper.py`) and the app's (`helab/views` with its `plots` package, `helab/utils`, `helab/models` and `main.py`, less `NOT_GUI`) and fails on a kind sent but not declared or declared but not sent, a kind the app matches that nothing sends (`GUI_KINDS` aside), and one the app is sent but never matches (`RECEIPTS` aside); `NOT_EVENTS` lists helper dicts with a `kind` that aren't events. Deferred deletes are sent after every test, also when its teardown raises, and a test that leaves a `QWebEngineView` alive fails (one deleted later crashed Qt; `tests/test_left_widgets.py`). The summary prints "rerun reasons" (why each rerun failed): quote them when reporting a RERUN. In CI logs, rerunfailures sleeps `--reruns-delay` before it logs RERUN, so subtract it (5 s on CI) from a rerun's apparent duration. A worker "crashed" under xdist with no traceback is usually `--timeout` (CI: 120 s), whose stacks xdist drops: look for the faulthandler dump at 100 s (`faulthandler_timeout`, `pytest.ini`). An exception Qt raised from C, with no traceback, gets a note naming the code that was running Qt's event loop (`where_qt_raised`, `tests/conftest.py`), and a cache left quitting by a test is shut down before the next (`no_quitting_cache`). Offline tests (`tests/test_offline_browsing.py`) deny source access with `no_source_io` (no source operation reaches `IOService._start`) and `deny_source` (`os.scandir`, `stat`, `lstat`, `listdir` and `open` of the source tree fail the test); tests that call `set_offline` reset `folder_cache._offline`. pytest-qt's Qt log capture is off (`--no-qt-log`, `pytest.ini`): its per-test swap of Qt's message handler raced with QtWebEngine logging from another thread (Ubuntu teardown errors); Qt messages show in captured stderr.

Windows: if pytest crashes during cleanup with `WinError 5` for
`pytest-current`, use either option in PowerShell:

```powershell
pytest --basetemp="$env:TEMP/helab-pytest-fresh"
pytest --basetemp=.ai/temp/pytest-fresh
```

Use a dedicated scratch directory per concurrent run: pytest clears it at startup.
See [investigation notes](../sessions/2026-10-13-codex-windows-pytest/notes.md)
for details and a separate intermittent cache-move failure.

`tests_sample_data/` (tracked, 12 MB, 43 files) holds a few shots from the lab: `goodish/` (`d<N>.txt` and `d_txy_forc<N>.txt` pairs 1–10 with the run's two MATLAB logs), `bad/` (pairs with gaps) and `bad_txy/` (shot 256). It is inside the checkout, so the source guard allows it (`tests/test_real_data_guard.py`), and it is one of `constants.DEV_POTENTIAL_DATA_PATHS`. `tests/test_convert_reference.py` reproduces its raw/TXY pairs byte for byte, so the folder has a `.gitattributes` `* -text` (as `tests/data/convert/` does): Windows CI's autocrlf would otherwise rewrite the LF TXY files (a guard test checks they have no CR). `tests/test_windows_paths.py` fails on any tracked path Windows can't check out (reserved names such as `nul.txt`, `<>:"|?*`, a trailing dot or space): one such file once stopped every Windows CI job at checkout. Two opt-in tests are skipped unless set: `HELAB_TEST_NATIVE_ICONS` (macOS native folder and volume icons, `tests/test_folder_icons.py`) and `HELAB_TEST_REAL_VOLUME=1` (this machine's volume IDs, `tests/test_data_roots.py`).

Slow tests first (Quick Fixes 6, 2026-10-29): `tests/conftest.py`'s `pytest_collection_modifyitems` puts the modules in `SLOW_FIRST_MODULES` (today `tests/test_typing.py`) at the start of each xdist worker's first batch (`slow_first_positions`, which mirrors xdist's `LoadScheduling` first batches), so they overlap the suite instead of forming a serial tail; a new module as slow belongs in that list. Each mypy test there has its own `--cache-dir` (`.mypy_cache/test_typing/<name>`, ignored), because concurrent mypy runs sharing one SQLite cache crash. Two traps (Quick Fixes 4, 2026-10-29): patch process-wide functions (`os.scandir`, …) only for the test's own thread, since `IOService.release` runs `shutil.rmtree` on a daemon thread (`HeLab-artifact-cleanup`); and don't `chdir` while helpers can start: they inherit the working folder, which the source guard denies outside the temp folder and the checkout (it shows only with `--basetemp` outside the checkout, so run the suite that way now and then). A path with spaces in the temp folder also catches tests that split paths on whitespace.

Tests ending in `.disabled` are intentionally skipped (not collected) — don't try to "fix" them into passing without checking why they were disabled first.
