## Running the suite

For the full suite, prefer the parallel form: `-n 12` runs 12 pytest-xdist workers (use at most the machine's CPU cores; CI uses `-n 4`). Never use `-n` without `--reruns` and `--reruns-delay` (pytest-rerunfailures): parallel workers can race (e.g. over temp folders) and Qt/timing tests fail now and then under load. Report any test that needed a `RERUN` rather than calling the run clean. Tests run Qt offscreen by default; set `HELAB_SHOW_GUI=1` to see the windows. `tests/conftest.py` gives every test's `tmp_path` a `.helab-root` and a fake volume ID (`temporary_data_root`); tests of RAM-only folders or of markers themselves opt out with `@pytest.mark.no_auto_data_root`. **Tests never touch real data** (Tony, 2026-10-20): conftest sets `HELAB_TEST_SOURCE_GUARD`, under which the helper (`helab/io_ops/infra.py`, `_guard`) refuses (`SourceRefused`, before touching it) any source path below `/Volumes`, `/Network`, `/net`, `/media`, `/mnt`, `/run/media` or `~/Library/CloudStorage`, a network or other-drive path on Windows, or inside `constants.DEV_POTENTIAL_DATA_PATHS`, unless it is inside the temp folder or this checkout; the refusal fails the test (`no_real_data`, `tests/test_real_data_guard.py`), and new tabs start in an empty temp folder. A test of mounts uses paths that don't exist. Production code reads these test seams: `HELAB_TEST_LOCAL_MOUNT` (Windows: one local mount), `HELAB_TEST_VOLUME_ID` (a fixed volume ID) and `HELAB_TEST_READ_GATE=<dir>` (`helab/io_ops/infra.py` only: a TXY read of `<name>` waits until `<dir>/<name>.go` exists, sending nothing meanwhile, so tests order reads on every platform and a gate never opened is a stuck read; `tests/test_live_io.py`) and `HELAB_TEST_IO_TRACE=<folder>` (`helab/io_ops/infra.py` only: every helper appends each source-folder operation to its own `<folder>/<pid>.jsonl`, as Help › Record I/O trace does; `tests/test_io_trace.py`) and `HELAB_REQUIRE_BACKENDS=cython,rust,…` (`tests/conftest.py`: a named converter backend that can't load stops the run, and a skip naming one fails; CI's converter-backends job sets it) and `HELAB_TEST_SETTINGS_FILE=<file.ini>` (`helab/utils/settings_store.py`: `app_settings()` opens that ini instead of the native store; `tests/conftest.py` gives every test its own) and `HELAB_UNITS_PLATFORM_OVERRIDE` (`number_format.PLATFORM`, read once at import: the platform whose byte units HeLab shows, `sys.platform` when unset; conftest pins `darwin`, so labels compare the same on every OS; test Windows' units with `platform="win32"`, by patching `number_format.PLATFORM` (call time), or in a fresh interpreter for what is set at import: the disk budget's default and minimum, `app_log.MB`, `test_units_set_at_import_follow_the_platform`; `HELAB_UNITS_PLATFORM_OVERRIDE=win32 helab` shows Windows' units on a Mac, and helpers inherit it). `tests/conftest.py` points the cache, temp and app folders at private temp folders (`HELAB_DIR_*_OVERRIDE`, `HELAB_APP_DIR_OVERRIDE`), which `helab.utils.constants` reads once at import: never import helab before pytest loads conftest (e.g. a script calling `pytest.main()` after its own helab imports; patch from a fixture instead). Conftest refuses to run then, since tests would write into the real cache. A script that imports helab outside pytest (a render or debug script) should set those three variables first too.

## Isolation, seams and fixtures

`pytest.ini` sets `pythonpath = .`, so pytest tests the checkout it runs in, whatever the venv's editable install or `PYTHONPATH` names (`tests/test_test_isolation.py`). Each test gets a disk cache store of its own (`private_store` in `tests/conftest.py`: `cache_dir()` and the helpers' `HELAB_DIR_CACHES_OVERRIDE`), so nothing a test saves reaches another. Before a test deletes a store through real helpers, it waits with `store_free(*services)` (`tests/conftest.py`) until neither its services nor the app-wide one has a cache helper running or unconfirmed. The app-wide IOService and FolderCache last a worker's run: real-window tests that change their state (Work Offline, quitting) restore it (`back_online`, `no_quitting_cache`), and a test may not assume no other service starts work during it. **Source runs driven by computer use (macOS):** `python dev/dev_app.py [--env-file .ai/local/floor-env.sh]` builds `.ai/local/HeLab-dev.app` (bundle ID `au.edu.anu.he-bec-lab.dev`, its own `--tag` for a second checkout); `open` it, never `venv/bin/helab`, and quit it before opening it again (`open` while it runs drops the new arguments; `open -n` makes a second instance with the same ID). With `floor-env.sh` the log is in the floor's app folder (`HELAB_APP_DIR_OVERRIDE`). **Accessible names** (`tests/test_accessible_names.py`): it opens each window and dialog (the main window with a synthetic folder, plots tabbed, released and floating; again with every script of every group and Counts per shot in each Library; Settings at each tab; eleven dialogs and tool windows; six message boxes HeLab builds, `ASKS`), walks every interactive control (`QAbstractButton`, `QComboBox`, `QLineEdit`, `QAbstractSpinBox`, `QAbstractSlider`, `QTabBar` and each tab, `QAbstractItemView`, editable text edits; less a control's own parts) and fails on any without a name or ID, or whose ID repeats among its window's shown controls. PyQt6 doesn't bind `QAccessible`, so `effective_name` follows Qt 6.11's rules. `test_every_widget_class_is_walked_or_skipped_with_a_reason` imports `helab/views`, `helab/analysis` and `helab/scripts` and fails on a `QWidget` subclass no case opens and `SKIPPED` doesn't list; `INLINE_SKIPPED` lists, with why, dialogs Qt builds itself. A new window or dialog: add a builder to `DIALOGS` (or a case with `@covers`); a new message box: an entry in `ASKS`. Window tests that load data but don't check caching use RAM-only folders (`no_auto_data_root`), so quitting never waits on a save. `tests/test_helper_events.py` reads the helper's side (`helab/io_ops/`, `io_helper.py`) and the app's (`helab/views` with its `plots` package, `helab/utils`, `helab/models`, `main.py` and the headless converter's `convert_cli.py`, less `NOT_GUI`) and fails on a kind sent but not declared or declared but not sent, a kind the app matches that nothing sends (`GUI_KINDS` aside), and one the app is sent but never matches (`RECEIPTS` aside); `NOT_EVENTS` lists helper dicts with a `kind` that aren't events. Deferred deletes are sent after every test, also when its teardown raises, and a test that leaves a `QWebEngineView` alive fails (one deleted later crashed Qt; `tests/test_left_widgets.py`). The summary prints "rerun reasons" (why each rerun failed): quote them when reporting a RERUN. In CI logs, rerunfailures sleeps `--reruns-delay` before it logs RERUN, so subtract it (5 s on CI) from a rerun's apparent duration. A worker "crashed" under xdist with no traceback is usually `--timeout` (CI: 120 s), whose stacks xdist drops: look for the faulthandler dump at 100 s (`faulthandler_timeout`, `pytest.ini`). An exception Qt raised from C, with no traceback, gets a note naming the code that was running Qt's event loop (`where_qt_raised`, `tests/conftest.py`), and a cache left quitting by a test is shut down before the next (`no_quitting_cache`). **store-v4's tests** turn the switch on with `switch_on` (`tests/test_store_v4.py`: the `store_v4` row in the test's ini plus `cache_store._reset_live_layout()`); the switch is read once per process, so a test that changes it resets the layout. Offline tests (`tests/test_offline_browsing.py`) deny source access with `no_source_io` (no source operation reaches `IOService._start`) and `deny_source` (`os.scandir`, `stat`, `lstat`, `listdir` and `open` of the source tree fail the test); tests that call `set_offline` reset `folder_cache._offline`. pytest-qt's Qt log capture is off (`--no-qt-log`, `pytest.ini`): its per-test swap of Qt's message handler raced with QtWebEngine logging from another thread (Ubuntu teardown errors); Qt messages show in captured stderr.

**Settle time and destroyed signals** (`agent/ui-polish`, landed `c104502`): `tests/test_settle_setting.py` checks that every helper route runs with the request's `settle_seconds`; `HELAB_SETTLE_SECONDS` (conftest's 0) wins over the request, so tests that need the request's value patch `fingerprints._SETTLE_OVERRIDE`. `tests/test_destroyed_connections.py` is an AST guard (no `.destroyed.connect(` to anything but a bound method in `helab/`, including `connect(slot=…)`, `destroyed[QObject]` and a signal stored in a name first) plus a closed Plotly plot's figure leaving `dash_server` at once. A test that waits for a close to free something never calls `gc.collect()` in its wait: it would hide a release that only a collection makes. Sibling test modules are imported by bare name (`from test_x import …`), never `tests.test_x` (mypy sees the file twice). `test_user_tags.py`'s deep-path test runs only its "converts" branch on GitHub's Windows runners (long paths on); the "too long" branch is covered by the patched tests.

## Windows

Windows: if pytest crashes during cleanup with `WinError 5` for
`pytest-current`, use either option in PowerShell:

```powershell
pytest --basetemp="$env:TEMP/helab-pytest-fresh"
pytest --basetemp=.ai/temp/pytest-fresh
```

Use a dedicated scratch directory per concurrent run: pytest clears it at startup.

## Sample data and opt-in tests

`tests_sample_data/` (tracked, 12 MB, 43 files) holds a few shots from the lab: `goodish/` (`d<N>.txt` and `d_txy_forc<N>.txt` pairs 1–10 with the run's two MATLAB logs), `bad/` (pairs with gaps) and `bad_txy/` (shot 256). It is inside the checkout, so the source guard allows it (`tests/test_real_data_guard.py`), and it is one of `constants.DEV_POTENTIAL_DATA_PATHS`. `tests/test_convert_reference.py` reproduces its raw/TXY pairs byte for byte, so the folder has a `.gitattributes` `* -text`, as `tests/data/convert/` (the converter's fixtures, also compared byte for byte) does: Windows CI's autocrlf would otherwise rewrite the LF TXY files (a guard test checks they have no CR). `tests/test_windows_paths.py` fails on any tracked path Windows can't check out (reserved names such as `nul.txt`, `<>:"|?*`, a trailing dot or space): one such file once stopped every Windows CI job at checkout. Two opt-in tests are skipped unless set: `HELAB_TEST_NATIVE_ICONS` (macOS native folder and volume icons, `tests/test_folder_icons.py`) and `HELAB_TEST_REAL_VOLUME=1` (this machine's volume IDs, `tests/test_data_roots.py`).

**HeLab's test data** (Q31.4) is the private Hugging Face dataset `TonyXTYan/HeLab-TestData`, built
by its `tools/build.py` from the local sample copies (`~/GitHub-Local/HeLab-testdata` on Tony's Mac):
a few raw/TXY pairs per detector era, Live, raw-only, TXY-only, nested and damaged folders, and
`reference/matlab-2023` (the only 2023-variant MATLAB output, M11.3), every file in its
`manifest.json` with its SHA-256. Tests pin a tag (`v1`; a change is a new tag). CI's
`.github/actions/testdata` downloads it with the `HF_TOKEN` secret (a read-only token), cached per
OS, and sets `HELAB_TESTDATA` and `HELAB_REQUIRE_TESTDATA=1`; without the token (forks, the lab's copy)
the tests that need it skip. Locally it is the `testdata` submodule, pinned at the tag's commit and never
fetched by default (`update = none`: `git submodule update --init --checkout testdata`, with HF's git
credentials), or a download anywhere named by `HELAB_TESTDATA`, which wins. On Tony's Mac,
`~/GitHub-Local/HeLab-testdata` is a symlink to the submodule (git refuses a symlink at a submodule's path).
A new tag: upload, tag, then move the submodule and the action's `--revision` together. `tests/test_convert_testdata.py` checks the
manifest and converts every pair byte for byte (`matlab-2019` on the eras, with its listed archive
faults; `matlab-2023-lab-edit` on the reference), by numpy and, in the Converter backends job,
cython. Tests only read it; one that writes copies it into its temp folder first.

## Slow tests first

Slow tests first (Quick Fixes 6, 2026-10-29): `tests/conftest.py`'s `pytest_collection_modifyitems` puts the modules in `SLOW_FIRST_MODULES` (today `tests/test_typing.py`) at the start of each xdist worker's first batch (`slow_first_positions`, which mirrors xdist's `LoadScheduling` first batches), so they overlap the suite instead of forming a serial tail; a new module as slow belongs in that list. Each mypy test there has its own `--cache-dir` (`.mypy_cache/test_typing/<name>`, ignored), because concurrent mypy runs sharing one SQLite cache crash. `--test-group N/M` runs one group of the suite (CI: two per OS, A17.2): a test's group is `zlib.crc32(nodeid) % M + 1`, the `SLOW_FIRST_MODULES` tests dealt out in turn and still first inside their group; `config.stash[ALL_TESTS]` keeps the whole collection, which `tests/test_test_groups.py` checks splits once. Two traps (Quick Fixes 4, 2026-10-29): patch process-wide functions (`os.scandir`, …) only for the test's own thread, since `IOService.release` runs `shutil.rmtree` on a daemon thread (`HeLab-artifact-cleanup`); and don't `chdir` while helpers can start: they inherit the working folder, which the source guard denies outside the temp folder and the checkout (it shows only with `--basetemp` outside the checkout, so run the suite that way now and then). A path with spaces in the temp folder also catches tests that split paths on whitespace.

## Disabled tests

Tests ending in `.disabled` are intentionally skipped (not collected) — don't try to "fix" them into passing without checking why they were disabled first.
