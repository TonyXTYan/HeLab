## Responsive filesystem I/O

**Responsive filesystem I/O:** The active folder browser uses `IOService` (`helab/utils/io_service.py`) and isolated `helab/io_helper.py` processes: that module is the process entry and dispatcher, each operation family a module of `helab/io_ops/` (browse, scanning, loading, save_held, live, convert, raw_fill, icons, markers, admin, results, listings, trace_check; `txy_cache`, a load's disk cache) over shared infrastructure (`infra`: tracing, traced calls, test seams, `Pause`, `Heartbeat`; `stores`, `fingerprints`, `metadata`, `summary`, `identity`). Nothing in `helab/io_ops/` imports `helab.io_helper` (it runs as `__main__`), and tests patch a name in the module that defines it. A name tests patch must be called as `module.name` from other modules, never imported by value (today `stores._cache_store`, `infra._volume_id_cache`, `infra._read_txy_file`, `fingerprints._raw_mtime`, `metadata._send_saved`, `markers._discover_root`, `provenance.read_shots` (called so by `helab_txy.find` and `convert`), `infra.emit` as `helab_txy._mark_used` calls it); also `folder_cache.store_options` (except in `helab/views/plots/arrangement.py` and `instance.py`, whose own copies the presets tests patch, and `helab/views/HelabMainWindow.py`, which imports it by value though tests patch only `folder_cache`'s), `cache_location.cache_location_problem`, `cache_location.share_of` (patched by the app's and `helab convert`'s tests; `tests/test_share_detection.py` checks no module of `helab/` imports it or `mount_table` by value), `explorer_convert.confirm_beside_on_share` (patched in `test_explorer_convert.py`; `explorer_live` calls it as `explorer_convert.confirm_beside_on_share`, `ExplorerConverter` bare in its own module), `fingerprints.RACY_SECONDS` (read by `live`) and `fingerprints.SETTLE_SECONDS` (read by `convert`; both also set per request by `fingerprints.configure_settle`, and tests patch them as before); names patched and read only in their own module (`presets.warning_box`, patched by conftest's `no_modal_warnings`; `convert._read_raw`, `scanning._scan`, `browse._mount_fingerprint`, the trace globals in `infra`; `stores._mounts`, `stores`' own by-value copy of `infra._mounts`, which the saved-listings tests patch) stay bare there. The helper's events are a typed contract in `helab/io_ops/events.py` (a `TypedDict` per event shape, their union `HelperEvent` and `KINDS`; standard library only, so the app can import it): `Emit` accepts only those, so strict mypy checks every event's fields where it is sent, and `tests/test_helper_events.py` checks the kinds the helper sends and the app matches on against it. `convert` (TXY conversion, [converter](converter.md)) is source I/O in the background slots, pausable like loads, refused by Work Offline, and held by a cache move like any request carrying `cache`. So is `raw_fill` (caching v2, store-v4 only, switch off; checkpoint 3, landed `c2d0ece`; [cache-store](cache-store.md#store-v4-caching-v2-behind-the-switch)): in `io_helper`'s `SOURCE_OPERATIONS` and `CACHE_ONLY` (refused without `cache`), `IOService`'s `PAUSABLE` and `CACHE_OPERATIONS`, labelled "Cache raw pulses"; its events are `raw_fill_done` (the shots saved, kept, refused) and `raw_overwritten` (Q28.6). With store-v4 on, each load's valid save is followed by a `raw_fill` that lists the folder once more in the background, on a share too (stage 1's design: raw pulses kept wherever HeLab caches; Q51.1, for Tony). A listing in store-v4 takes "disk cached" and `cache_info` from the folder's TXY view (`read_dataset_infos`, [cache-store](cache-store.md#store-v4-caching-v2-behind-the-switch); `4afa96a`), as do a scan's `cache_mismatch` and adopt; it also sends the folder's own TXY source and policy (`folder_choices`, from `metadata._send_saved`) and each child's in its entry's `choices`, only when set (A47.2). Loads and Live checks also read HeLab's folders under the cache and temp folders (`io_ops.helab_txy`, plain calls, not source I/O) and the base's `converted-txy/index.sqlite`, never created or set aside by a load, which only moves its folder's `last_used` on at most hourly; a use it doesn't write (that step, or the index busy past 200 ms) is sent as `txy_unmarked`, kept in `FolderCache` memory and written in the background about every 10 minutes and as HeLab quits (`cache_admin` `mark_used`, the index only; `admin_result`'s `unwritten` lists what a busy index left); `convert` and `helab convert` write it, and the GUI never opens it; FolderCache adds `txy` to every load (`with_txy`). `FolderCache` files and forgets its shared jobs by one `job_key(operation, path, live, choice)` (`SharedJob.choice`): a plot's own TXY choice loads as `load:<choice>`, forgotten when it ends like any other, so no dead job is joined and no arrays outlive the RAM budget (io-2). Requests are deduplicated, queues and concurrency are bounded, and cancellation/deadlines never wait on the GUI thread. Daemon reader threads deliver results through a bounded queue; a Qt timer applies small batches. A helper's stderr goes to `stderr.txt` in its private folder; when it exits without `done` or `error`, the last 2 KB are logged with the operation and path. Writing a Live save's held arrays to that folder counts as progress for the no-progress timer. Source folders are never queried by the GUI model. The GUI may read the OS mount table (`cache_location.mount_table`, cached 10 s: psutil's `getfsstat` without waiting on macOS, `/proc` on Linux, `GetDriveTypeW`/`WNetGetConnectionW` on Windows) to tell whether a folder is on a share (`share_of`, lexical: no stat or realpath; A39.5, [converter](converter.md#shares-a395)), and nothing below a mount point. The frozen helper entry point in `helab/main.py` must run before imports that initialize GUI services, caches, or Dash. `GUIWatchdog` records event-loop stalls and dumps thread stacks independently of GUI timers: the stall line goes to the log, the stacks to the process's stderr (`sys.__stderr__`), not the log.

## The shared I/O queue

Rules for the shared I/O queue (decisions, timings and the stopping-helper display: `.ai/memory/results/folder-io-queue.md`):
- One app-wide queue with three lane kinds (`IOService`: `FOREGROUND`, `BACKGROUND`, `LOCAL`): one foreground lane (`FOREGROUND_CAP` 3 processes) and N background slots for source I/O, and a local lane (`LOCAL_CAP` 2) that never touches source folders. The **foreground** lane runs the current tab's listings (`list`, `resolve`) and its selected load (in queue mode, its queued loads one at a time): one listing and one load at once, at most 3 processes including stopping ones, and it never waits for background work. The **background** slots (Settings → General, "Simultaneous background I/O operations", `simultaneous_folder_io_operations`, default 1) run everything else: background loads, `details`, basic scans, cache writes and history saves. `raw_fill` (caching v2, store-v4 only) runs there too, pausable and refused offline, one per folder (owner `raw_fill:<path>`, `FolderCache.schedule_raw_fill` after a valid `cache_saved`); it yields after about 30 s of work (`more`) and is queued again at the back, as is a folder asked for again while it runs, so scans and Live's saves never wait behind a large folder. Its no-progress timeout is `NO_PROGRESS_TIMEOUT`, fed by heartbeats while it lists, reads and encodes; it holds its slot until its exit is confirmed, and an error isn't retried until the next save asks. Navigation and loads precede bulk scans; FIFO within each group. A tab's Live checks run in its foreground lane but pause background work only while they read a file. `FolderCache` decides the lane (`foreground_owners`, set by the current `FolderExplorer`); switching tabs makes the old tab's work background.
- While the foreground works, background loads and scans **pause cooperatively** (a `pause` file in the helper's private folder, checked between files/entries; `paused`/`resumed` events) and no new ones start; the selected load pauses while the tab lists a folder. Resume is 0.5 s after the foreground goes idle; a listing silent for 3 s no longer counts. A paused helper keeps its slot and its no-progress timer is frozen. `pause_requested` changes only once the flag file is as asked, so a pause flag that couldn't be written or removed is tried again on the next tick (`_apply_pauses`, `_write_pause`; io-8). A load leaving the foreground takes a free background slot, or is stopped and requeued to restart from its RAM shots.
- **Automatic loads wait for the selection to settle** in Finish and Cancel modes (Queue mode keeps its 3 s wait): while a load is running, queued or stopping, or one started under 0.3 s ago, an automatic load starts only once the selection has stayed for 0.3 s plus 0.1 s per queued I/O task other than the folder's own, at most 1 s (`FolderExplorer.settle_seconds`); when idle it starts at once. Data in RAM shows at once; the cached read and the check wait. Tests set `SETTLE_MAX = 0` (`tests/conftest.py`). "Settle" means two things here: a *file* is settled once unmodified for the settle time (`SETTLE_SECONDS`, the setting, default 5 s, `fingerprints._settled`; below, and Live's "settled by age", which also wants it unchanged a check apart), and the *selection* settles after `FolderExplorer.settle_seconds` (0.3 s plus 0.1 s per queued task, at most `SETTLE_MAX` 1 s).
- The **local** lane (`LOCAL_OPERATIONS`, 2 processes) runs `cached` reads of the local disk cache, offline `saved_list` listings (Work Offline, below), batched `subtree_save` writes of derived subfolder status, `cache_admin` maintenance (the startup sweep) and `volumes_verify` (mounted volumes' IDs only, for data-root hints) and `cache_move`, `result_find` and `result_save`, and `trace_check` (before Help › Record I/O trace starts: the temp folder's network/synced check and its earlier recordings; 10 s no-progress timeout). They never touch source folders, never wait for or pause with foreground/background work, and are never paused. The user's `root_create`, `root_reassign` and `root_remove` (one marker write each) run in the foreground like a listing.
- **Work Offline** (File › Work Offline, remembered in `work_offline`; status-bar button "Offline · cached data only", which asks "Work online?"; `roadmaps/cache-only-browsing.md`, decisions in `.ai/sessions/2026-10-26-claude-cache-only/design.md`): no source-folder or network I/O. `IOService` starts only `OFFLINE_OPERATIONS` (`cached`, `saved_list`, `cache_admin`, `result_find`, `result_save`, `invalidate`, `volumes_verify`, `trace_check`, `cache_move`, `drives`), refuses the rest at `submit` (one INFO line per kind) and again at `_start`, and `set_offline(True)` cancels queued and running source work, finished ordinary loads' cache tails included (they re-read the folder: "Not cached: Work Offline stopped the save…", the data stays in RAM), but not saves asked for before it (`finishes_offline`, `before_offline`: Live's stop-save). `FolderCache.set_offline` (`offline`, `offlineChanged`) cancels shared jobs except those saves; its `submit` turns a tab's `list` into a local-lane `saved_list` (`io_ops/listings.saved_list_folder`: the folder's saved records, then its saved subfolders, then an `OfflineListingEvent`; no snapshot, no scan history), the start-up `resolve` into the newest data root, and answers any other source operation with `offline` (never a failure); no derived status is saved offline. `io_helper` refuses `OFFLINE_REFUSED` for an offline request before any handler. The tree shows saved listings ("Offline: showing saved results from <date>", "Subfolders: not listed while online"), no icon or details requests; selection shows RAM or one cached read ("not checked (offline)", "No cached data (offline)", "Data not kept (offline): work online to load it"); plots and saved results work. Refresh, Retry, Check folder status, Live, Place .helab-root, the marker dialog's Save to folder…, Load as it is now, It's a copy…, Data roots' Show in Finder and Delete .helab-root… are disabled ("Not while working offline"). Work Online cancels offline listings still in flight, verifies volumes and roots again, refreshes every tab and checks each selection.
- **Cache first.** Selecting a folder with a disk cache shows its data at once (memory, else a `cached` read), marked unchecked (`loaded (cached)` / `Checking for changes…`). The check is a load that runs **beside** the cached read (`cache_base`: it counts the cached shots as held; `FolderCache` holds its result until the read's dataset arrives; a failed or too-large read cancels it, and a plain load follows). Leaving the folder cancels a check that hasn't found files to read together with its read; one reading new files moves to the background with its read (Finish, Queue), and they stop together. Data in RAM counts as checked only for `FRESH_SECONDS`, after a load checked it or a scan of the folder found the same files (`FolderCache.counts_as_checked`, the one rule for the tab's label and for answering a load from memory; cached data counts only by such a scan), so returning to a folder later checks it again. When the cache has no unsettled files and the folder's mtime is exactly the one stat'ed just before the cache's listing (`info["folder_mtime_ns"]`, compared only with itself since it is the server's clock; None, so the next check lists, when within `RACY_SECONDS` = 2 s of the listing and after a Live save; caches without it compare with `snapshot_at`; `memory_check` carries the same value; `fingerprints._mtime_unchanged`), the helper answers `unchanged` without listing, after statting a sample of the cached TXY files (Settings → General → Check of cached data: Swift = last, Fast = first and last, Medium (default) = those plus max(3, 1%) random, High = plus max(10, 3%), Full = always list; names saved in the dataset info). The held dataset counts as the cached one (`loading._unchanged_since_cache`) only while its signature matches **and** every shot both have has the same (size, mtime) and kind (`held_origins` against the row's `txy.origins`): the signature is the folder's MATLAB TXY, and another HeLab on this computer may have saved the folder with a shot from another TXY; otherwise the load lists the folder and reuses RAM only for matching shots (Quick Fixes 7, Codex on PR #10, `8e11ffe`). A full listing that finds every cached TXY file unchanged, none still being written, records that without rewriting the dataset (`CacheStore.confirm_dataset`), and only when the cached signature is the folder's too; otherwise (a MATLAB TXY arrived or settled for a shot held from HeLab's) every cached shot is reused, no TXY is read and the dataset is saved again with the new signature (`loading.load`, io-5; in store-v4 A40.3's `confirm_view` writes only the view's signature and TXY record, nothing rewritten): `snapshot_at` moves to when it started, `unsettled` to 0, and older caches gain their names, so a later non-TXY change (Finder's `.DS_Store`) doesn't rule out the quick check for good. Otherwise it lists, fingerprints and merges as usual. Shots cached or held that the folder no longer lists stop the load before any file is read (`shots_missing`): TXY files are written once, so another folder may sit at that path; a folder status check or details scan finds the same from the dataset's record alone (`cache_mismatch`, no data read). The folder's data is dropped from RAM and not shown (`FolderCache.mismatched`: session-only, up to 8192 folders, oldest dropped first; never a load's base) until a load completes or its cached data is cleared. The tab's line says Retry after checking the drive (remounting the right one is a fix) and offers Review…, which opens the window with that folder selected. One app-wide, non-modal `MissingShotsWindow` lists them (newest first; status-bar "⚠ N mismatched" reopens it) with Load as it is now (`FolderExplorer.load_as_it_is_now` → `allow_missing`, used once) / Don't load. When the session's count reaches 2, 4, 8…, loads and scans pause and none start (`IOService.mismatch_hold`, `MISMATCH_HELD`; browsing, cached reads, cache saves and icons go on) until Resume or Cancel all loads and scans (`cancel_held`); saves (Live's too) and Live checks are spared (`IOService.mismatch_spared`: `payload.save` or `live`), neither held, paused nor cancelled, a selected load the hold pauses doesn't hold background work (`_foreground_busy` skips requests `held_by_mismatch`), and quitting lifts the hold after cancelling what it held (`FolderCache.cancel_for_quit`; io-1, io-6); from 8, Skip mismatched folders lists them silently for the session with no more holds. Selecting a folder with saved counts and a disk cache does not list it (expanding still does). A failed check keeps the cached data with `Check failed` and Retry. A repaired TXY file gets a new name; right-click Retry / Refresh makes the folder's next check (at once for the shown folder) compare every file's size and mtime (`full_check`), since a file rewritten in place doesn't change the folder's mtime.
- **I/O trace:** Help › Record I/O trace (this session), off at every start and never saved, records every helper's source-folder operations as JSON lines in a new recording folder `<temp folder>/io-traces/io-trace-<date>-<time>/`, one `<pid>.jsonl` per helper (Windows' C runtime emulates O_APPEND, so helpers never share a file; `IOService.trace_dir`, sent with each request); refused when the temp folder is on a network or synced folder; one INFO line when it starts and one when it stops (also on quit); a status-bar note while on; Help › Show I/O trace folder; earlier recordings are kept unless the user picks Delete old traces when asked. Summarise with `.ai/sessions/2026-10-19-claude-smb-io-audit/trace_summary.py`, compare with `compare_traces.py`. Data-root verification is asked only by a listing's new mount table (one follow-up, never self-requeued, 5 s backstop); a load's fingerprint comes from its listing; RAM-held data without a disk cache gets a quick check (`memory_check`); selecting a RAM-held leaf folder doesn't list it.
- **Files still being written** (modified within the settle time, with an mtime ahead of this PC's clock (Tony, 2026-10-22), or changing while read) are never read or cached: they are left out of fingerprints and signatures (loads and scans alike), counted as `still being written`, and the cache records `unsettled` so the next check is a full one. Tests set `HELAB_SETTLE_SECONDS=0`.
- **The settle time is a setting** (Q33.7, `agent/ui-polish`, landed `c104502`): `settle_seconds`, Settings › General "Read files unmodified for" under Live's check interval, default 5 s, 2–60 s (below 2 s HeLab can't tell a file still being written); limits and default in `helab/utils/settle_time.py` (standard library, shared by helpers and the app). It applies to every read: `HelabMainWindow._apply_live_settings` (at start and after Settings) sets `IOService.settle_seconds`, `IOService._start` stamps it on each attempt (`IORequest.settle`) and `_run` sends it as the payload's `settle_seconds` beside `trace`, on every request (list, details, scan, load, Live checks and saves, cached reads, conversions, the local lane's operations). `io_helper.main` calls `fingerprints.configure_settle(request.get("settle_seconds"))` before the trace and any handler: it sets `SETTLE_SECONDS` and `RACY_SECONDS = min(2, settle)` (so 2 s in practice), which every read already takes when it runs. Without the field (`helab convert`, which reads no settings; an older HeLab's request; an in-process caller) or with a value that isn't a finite number, the default 5 s; a number out of range takes the nearest limit; `HELAB_SETTLE_SECONDS`, when set, wins over the request (tests keep 0). `helab convert --once` still wants 60 s (`ONCE_SETTLE_SECONDS`). The helper's I/O trace has `settle` on every line.
- **Shot times** (DLD D7): a shot's time is its raw `d<N>.txt` file's mtime (Tony, 2026-10-20: raw files are never rewritten; a TXY's mtime is when it was converted). A load's, Live check's or Live save's own listing keeps the raw entries and stats one (reasons `load: shot time`, `live: shot time`, `save: shot time`; free on Windows, where the listing has the stat) only for a shot whose time isn't known: never for shots cached or held in RAM with a time (`FolderCache` sends held shots' times as `memory_raw_times` with `memory`, and as `held_raw_times` with Live's save), never in quick checks or cached reads. A known time is kept only while the shot's TXY fingerprint is unchanged (a run copied over the folder gets its own times), and a raw file modified within `SETTLE_SECONDS` gives no time yet (`io_ops.fingerprints._raw_mtime`). Raw files never enter fingerprints, signatures or reuse; a deleted raw file keeps the shot and its time. Without a raw time a shot's time is its TXY fingerprint's mtime, flagged (`DatasetView.shot_time` / `shot_times` / `fallback_times`).
- A helper occupies its slot **until its exit is confirmed** by the daemon reaper's in-memory exit flag — including cancelled/timed-out helpers and background cache writers. Never free a slot on message delivery or reader completion; duplicate exit notifications are matched by request identity. `IOService.shutdown` kills every retired helper still running itself (`poll`/`kill`, never a wait), as well as through the reapers, which still confirm the exits (a helper still being started then is stopped only by `_run`'s thread, A40.1).
- Browsing is two steps. `list` (one scandir, names only; the only stat is its own `.helab-root`'s, for data roots) gives counts and status at once, plus each subfolder's saved summary, history and cache flags from the local cache — so saved badges appear immediately and automatic visible scans don't redo them. `details` (the full scan) follows in the background for the signature and dates; subfolder dates come from the listing's entries (`_entry_stat(..., follow_symlinks=False)`: no call per subfolder on Windows). Saved status is a last-known result keyed by data root (root UUID and relative path; the SMB share is only a location) on disk, and by source path in session memory: a changed observed folder mtime adds the amber clock, and only that folder's own completed status check replaces its result. A status check or details scan that finds a folder's signature changed drops its datasets (`FolderCache._folder_changed`) but leaves its running load, Live check and cached read; only a clear (`_invalidate_data`) cancels them: every load and cached read of the folder, a plot's own choice included, and a delivery waiting on one is told `cancelled` (io-2). The RAM budget spares a cached read's dataset while a check waits for it (`_awaiting_producers`, until `_resume_awaiting`; io-7). Inodes and mount device numbers never invalidate saved status or scan-failure history. It is skipped while a load of a folder **without subfolders** runs — the load sends and saves the same folder summary. A listing writes only root-discovery records (`roots`, `root_volumes`, a nested root's re-key) and never clears a scan failure; a listing error records one. An empty `signature` means unknown, never "changed".
- Timeouts measure **time without progress**; helpers send heartbeats while listing or checking files. Listings, scans and a load's listing phase get one 60 s attempt with no retry (a timeout is one scan failure). Only a load's per-file reads retry, with 15/20/30 s attempts per file. Right-click Retry / Refresh and the status-line Retry list one folder with no timeout, showing elapsed time and a Cancel action; a load retry keeps its per-file timeouts. **A retry never runs beside the attempt it replaces** — it is held until that helper exits. Cancellation stops retries. Timed-out loads restart from completed RAM shots after fingerprint validation.

## Loads with TXY layers

**Loads with TXY layers** (caching v2 stage 2, store-v4 only, switch off; landed `1cd586c`; [cache-store](cache-store.md#txy-layers-stage-2)): `io_ops/txy_cache.py`'s `Access` makes the calls `_load` and `save_held` made on the dataset row (`row`, `full` with a loader, `touch`, `confirm`, `write`): in store-v3 they are the dataset methods, as before; in store-v4 a view stands in for the row and its shots come from their layers, so the quick check, `whole`, `same_kind` and the missing-shot rule are unchanged. **The loading order**, per shot of the composition (`helab_txy.compose` / `txy_sources.choose`, unchanged): (1) its layer, with the current fingerprint (Q45.3's kind included) and the entry key the view saved (C-1); (2) for a HeLab shot, the raw layer converted with the layer's profile, equal to its text (`6f57918`; the conversion profile sent whole since A47.1, `912f928`, and Settings' backend since A47.6, `9e8c576`), run **before the shot's `file_started`**, under the converter's `_Ticker` (`compute_budget` of the raw size), in the load's read and the save's re-read, so IOService's per-file 15/20/30 s window never covers it and its heartbeats count as progress; it sends no file events and counts as read (S3-2); (3) with no view yet, store-v4's own `datasets` row, else store-v3's under Keep, copied into the layers by the load's save (Q45.4, Q45.5); (4) the share; and (stage 3, below) for an on-read candidate with neither layer, converting its raw file. A save writes one unit of what the layers lack; a held shot already kept isn't read again for it. Every v4 listing marks its sources seen (`mark_txy_seen`), each layer against its own source (C-2). Each job takes a TXY guard beside its dataset guard. **Cached reads** carry the tab's TXY source (FolderCache's `with_txy` adds `txy` to `cached` too; `io_helper.py` passes it); an older request reads the folder's last used view. **A plot's own TXY choice** (a `no_cache` request) is cached under its own view in store-v4, quietly: no cache events, never waiting (`hold`); Don't cache still keeps it RAM only (Q19.3). **A folder's own choices** (Q45.1, Q45.2): a v4 load sends `folder_choices` (source, tag, policy), which `FolderCache` remembers (`folder_choices`, `set_folder_choice`: kept at once, then saved by the admin's `folder_choice`) and `with_txy` applies to the tab's loads, Live and cached reads (`txy_sources.with_choices`; a tag resolves to the conversion profile or a built-in). Policy goes with store-v4 requests only (`store_options`' `policy`), so store-v3's options are unchanged.

**Loads convert on read** (caching v2 stage 3, `912f928`–`4e14535`, review fixes `97c2554`, landed `d4f28f3`; store-v4 only, switch off, store-v3 unchanged; Q50.3–Q50.8): when the source reads HeLab's TXY, a shot with a raw `d<N>.txt` and no current HeLab text of the profile asked for is an on-read candidate (`helab_txy.on_read`: its `HelabShot` names the raw file, keyed by its stat, so the settle time applies to the raw file), and `compose` picks it or MATLAB's text by the source's rule (`could_take`, `choose`). Which shots convert over MATLAB's TXY is `txy_sources.converts_over_matlab` (Q50.1 (a), Tony 2026-11-03; `ced04aa`): HeLab only, all; HeLab priority, only the shots MATLAB's TXY lacks (`CONVERT_OVER_MATLAB` False: converting over MATLAB's had a raw file that couldn't be converted yet, still settling or damaged, cost the shot its MATLAB TXY); MATLAB's sources, never. `on_read` takes the shots Live holds (`held`) and spares those held from HeLab, as `could_take` does, so a shot Live converted on read stays HeLab's when MATLAB's TXY appears (SQ-1, `9be3e12`). It is served by its layer, then the raw layer, then `txy_cache.convert_raw_file` ([converter](converter.md)): late (an unfinished raw file) waits for the next load, damaged and failed are judged as `helab convert --once` judges them, and a file with no hits is an empty shot. The shot is saved in the HeLab layer as kind `raw`; loads write no text and no raw row (R~1, R~2: `raw_fill` keeps filling the raw layer). `with_txy` sets `on_read` on store-v4 loads and Live checks and sends the profile whole. `load_counts` gains `helab_on_read` and `converted` (`txy_helab` stays the count of HeLab texts); the dataset's `txy` record gains `on_read`. **Counts before a load** (S3-5, Q50.7): `FolderCache.converts_on_read(path)` holds in store-v4 with a source that reads HeLab's and the folder cached; `on_read_shots` follows what the load would do (the same rule: MATLAB priority and HeLab priority, the raw files MATLAB's TXY lacks; HeLab only, every raw file; once loaded, the load's own `helab_on_read`; S3R-2, `ced04aa`), from memory only, read by the row tooltip's Here line, the count line, Folder details, the status bar's "not loaded" message, auto-load (`_has_data`) and Live launch's first load (`FolderExplorer.on_read_count`).

**Loads under a TXY list** (Q53.2, Q55.1, Q55.2; `agent/txy-priority`, landed `9bf99ff`; [converter](converter.md#txy-priority-lists)): loads, Live checks and saves compose with `helab_txy.find_list` and `compose_list` over the chain (`chain_of`: the own entries, the payload's `fallback`, External, then the any-HeLab stage `_find_any`), each stage's `find` narrowed to shots no earlier stage has a file of (the generalisation of `could_take`; `find` gains `look_in_folders`, `on_read` gains `over_matlab`). Beside TXY are kept by tag (`Beside`); a list of several entries keeps every tag. **The held-shot rule** is exactly `choose(held=…)` for the four modes; a held shot keeps a fallback stage only while no entry of its own list has it. Loads and Live reclaim it for that entry (Live reads it again, External feeding the mismatch rule meanwhile, as A39.2's switch); Live's save never does (`save_held` composes with `reclaim=False`; TP-3, `8f250df`). Under store-v4 the helper's folder-row step resolves tags from what the app resolved and sent (`helab_txy.tag_lookup`: the mode's profile, the entries, `known`, `conversion`, then the built-ins), so a user-profile row stays that profile (TP-1). ## Folder icons

**Folder icons:** The name column starts with a generic folder icon. Visible rows get native folder/volume icons (including macOS custom icons) from a separate `icons` helper in the shared background I/O lane, in batches of at most 64 with a 5-second no-progress timeout and cooperative pausing. `FolderCache` holds up to 4096 icons in session memory, shared across tabs; failed lookups retain the generic icon until Refresh. Icon lookup never runs during listing or model rendering. Refresh clears visible icons for another lookup. Keep the native Qt platform plugin in the helper; offscreen Qt cannot supply macOS custom icons.
