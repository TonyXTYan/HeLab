## Responsive filesystem I/O

**Responsive filesystem I/O:** The active folder browser uses `IOService` (`helab/utils/io_service.py`) and isolated `helab/io_helper.py` processes: that module is the process entry and dispatcher, each operation family a module of `helab/io_ops/` (browse, scanning, loading, save_held, live, convert, icons, markers, admin, results, listings, trace_check) over shared infrastructure (`infra`: tracing, traced calls, test seams, `Pause`, `Heartbeat`; `stores`, `fingerprints`, `metadata`, `summary`, `identity`). Nothing in `helab/io_ops/` imports `helab.io_helper` (it runs as `__main__`), and tests patch a name in the module that defines it. A name tests patch must be called as `module.name` from other modules, never imported by value (today `stores._cache_store`, `infra._volume_id_cache`, `infra._read_txy_file`, `fingerprints._raw_mtime`, `metadata._send_saved`, `markers._discover_root`, `provenance.read_shots` (called so by `helab_txy.find` and `convert`), `infra.emit` as `helab_txy._mark_used` calls it); also `folder_cache.store_options` (except in `helab/views/plots/arrangement.py` and `instance.py`, whose own copies the presets tests patch, and `helab/views/HelabMainWindow.py`, which imports it by value though tests patch only `folder_cache`'s), `cache_location.cache_location_problem`, `fingerprints.RACY_SECONDS` (read by `live`) and `fingerprints.SETTLE_SECONDS` (read by `convert`); names patched and read only in their own module (`convert._read_raw`, `scanning._scan`, `browse._mount_fingerprint`, the trace globals in `infra`; `stores._mounts`, `stores`' own by-value copy of `infra._mounts`, which the saved-listings tests patch) stay bare there. The helper's events are a typed contract in `helab/io_ops/events.py` (a `TypedDict` per event shape, their union `HelperEvent` and `KINDS`; standard library only, so the app can import it): `Emit` accepts only those, so strict mypy checks every event's fields where it is sent, and `tests/test_helper_events.py` checks the kinds the helper sends and the app matches on against it. `convert` (TXY conversion, [converter](converter.md)) is source I/O in the background slots, pausable like loads, refused by Work Offline, and held by a cache move like any request carrying `cache`. Loads and Live checks also read HeLab's folders under the cache and temp folders (`io_ops.helab_txy`, plain calls, not source I/O) and the base's `converted-txy/index.sqlite`, never created or set aside by a load, which only moves its folder's `last_used` on at most hourly; a use it doesn't write (that step, or the index busy past 200 ms) is sent as `txy_unmarked`, kept in `FolderCache` memory and written in the background about every 10 minutes and as HeLab quits (`cache_admin` `mark_used`, the index only; `admin_result`'s `unwritten` lists what a busy index left); `convert` and `helab convert` write it, and the GUI never opens it; FolderCache adds `txy` to every load (`with_txy`); another source's load has its own job key `load:<source>`. Requests are deduplicated, queues and concurrency are bounded, and cancellation/deadlines never wait on the GUI thread. Daemon reader threads deliver results through a bounded queue; a Qt timer applies small batches. A helper's stderr goes to `stderr.txt` in its private folder; when it exits without `done` or `error`, the last 2 KB are logged with the operation and path. Writing a Live save's held arrays to that folder counts as progress for the no-progress timer. Source folders are never queried by the GUI model. The frozen helper entry point in `helab/main.py` must run before imports that initialize GUI services, caches, or Dash. `GUIWatchdog` records event-loop stalls and dumps thread stacks independently of GUI timers: the stall line goes to the log, the stacks to the process's stderr (`sys.__stderr__`), not the log.

## The shared I/O queue

Rules for the shared I/O queue (decisions, timings and the stopping-helper display: `.ai/memory/results/folder-io-queue.md`):
- One app-wide queue with three lane kinds (`IOService`: `FOREGROUND`, `BACKGROUND`, `LOCAL`): one foreground lane (`FOREGROUND_CAP` 3 processes) and N background slots for source I/O, and a local lane (`LOCAL_CAP` 2) that never touches source folders. The **foreground** lane runs the current tab's listings (`list`, `resolve`) and its selected load (in queue mode, its queued loads one at a time): one listing and one load at once, at most 3 processes including stopping ones, and it never waits for background work. The **background** slots (Settings → General, "Simultaneous background I/O operations", `simultaneous_folder_io_operations`, default 1) run everything else: background loads, `details`, basic scans, cache writes and history saves. Navigation and loads precede bulk scans; FIFO within each group. A tab's Live checks run in its foreground lane but pause background work only while they read a file. `FolderCache` decides the lane (`foreground_owners`, set by the current `FolderExplorer`); switching tabs makes the old tab's work background.
- While the foreground works, background loads and scans **pause cooperatively** (a `pause` file in the helper's private folder, checked between files/entries; `paused`/`resumed` events) and no new ones start; the selected load pauses while the tab lists a folder. Resume is 0.5 s after the foreground goes idle; a listing silent for 3 s no longer counts. A paused helper keeps its slot and its no-progress timer is frozen. A load leaving the foreground takes a free background slot, or is stopped and requeued to restart from its RAM shots.
- **Automatic loads wait for the selection to settle** in Finish and Cancel modes (Queue mode keeps its 3 s wait): while a load is running, queued or stopping, or one started under 0.3 s ago, an automatic load starts only once the selection has stayed for 0.3 s plus 0.1 s per queued I/O task other than the folder's own, at most 1 s (`FolderExplorer.settle_seconds`); when idle it starts at once. Data in RAM shows at once; the cached read and the check wait. Tests set `SETTLE_MAX = 0` (`tests/conftest.py`). "Settle" means two things here: a *file* is settled once unmodified for `SETTLE_SECONDS` (5 s, `fingerprints._settled`; below, and Live's "settled by age", which also wants it unchanged a check apart), and the *selection* settles after `FolderExplorer.settle_seconds` (0.3 s plus 0.1 s per queued task, at most `SETTLE_MAX` 1 s).
- The **local** lane (`LOCAL_OPERATIONS`, 2 processes) runs `cached` reads of the local disk cache, offline `saved_list` listings (Work Offline, below), batched `subtree_save` writes of derived subfolder status, `cache_admin` maintenance (the startup sweep) and `volumes_verify` (mounted volumes' IDs only, for data-root hints) and `cache_move`, `result_find` and `result_save`, and `trace_check` (before Help › Record I/O trace starts: the temp folder's network/synced check and its earlier recordings; 10 s no-progress timeout). They never touch source folders, never wait for or pause with foreground/background work, and are never paused. The user's `root_create`, `root_reassign` and `root_remove` (one marker write each) run in the foreground like a listing.
- **Work Offline** (File › Work Offline, remembered in `work_offline`; status-bar button "Offline · cached data only", which asks "Work online?"; `roadmaps/cache-only-browsing.md`, decisions in `.ai/sessions/2026-10-26-claude-cache-only/design.md`): no source-folder or network I/O. `IOService` starts only `OFFLINE_OPERATIONS` (`cached`, `saved_list`, `cache_admin`, `result_find`, `result_save`, `invalidate`, `volumes_verify`, `trace_check`, `cache_move`, `drives`), refuses the rest at `submit` (one INFO line per kind) and again at `_start`, and `set_offline(True)` cancels queued and running source work, finished ordinary loads' cache tails included (they re-read the folder: "Not cached: Work Offline stopped the save…", the data stays in RAM), but not saves asked for before it (`finishes_offline`, `before_offline`: Live's stop-save). `FolderCache.set_offline` (`offline`, `offlineChanged`) cancels shared jobs except those saves; its `submit` turns a tab's `list` into a local-lane `saved_list` (`io_ops/listings.saved_list_folder`: the folder's saved records, then its saved subfolders, then an `OfflineListingEvent`; no snapshot, no scan history), the start-up `resolve` into the newest data root, and answers any other source operation with `offline` (never a failure); no derived status is saved offline. `io_helper` refuses `OFFLINE_REFUSED` for an offline request before any handler. The tree shows saved listings ("Offline: showing saved results from <date>", "Subfolders: not listed while online"), no icon or details requests; selection shows RAM or one cached read ("not checked (offline)", "No cached data (offline)", "Data not kept (offline): work online to load it"); plots and saved results work. Refresh, Retry, Check folder status, Live, Place .helab-root, the marker dialog's Save to folder…, Load as it is now, It's a copy…, Data roots' Show in Finder and Delete .helab-root… are disabled ("Not while working offline"). Work Online cancels offline listings still in flight, verifies volumes and roots again, refreshes every tab and checks each selection.
- **Cache first.** Selecting a folder with a disk cache shows its data at once (memory, else a `cached` read), marked unchecked (`loaded (cached)` / `Checking for changes…`). The check is a load that runs **beside** the cached read (`cache_base`: it counts the cached shots as held; `FolderCache` holds its result until the read's dataset arrives; a failed or too-large read cancels it, and a plain load follows). Leaving the folder cancels a check that hasn't found files to read together with its read; one reading new files moves to the background with its read (Finish, Queue), and they stop together. Data in RAM counts as checked only for `FRESH_SECONDS`, after a load checked it or a scan of the folder found the same files (`FolderCache.counts_as_checked`, the one rule for the tab's label and for answering a load from memory; cached data counts only by such a scan), so returning to a folder later checks it again. When the cache has no unsettled files and the folder's mtime is exactly the one stat'ed just before the cache's listing (`info["folder_mtime_ns"]`, compared only with itself since it is the server's clock; None, so the next check lists, when within `RACY_SECONDS` = 2 s of the listing and after a Live save; caches without it compare with `snapshot_at`; `memory_check` carries the same value; `fingerprints._mtime_unchanged`), the helper answers `unchanged` without listing, after statting a sample of the cached TXY files (Settings → General → Check of cached data: Swift = last, Fast = first and last, Medium (default) = those plus max(3, 1%) random, High = plus max(10, 3%), Full = always list; names saved in the dataset info). A full listing that finds every cached TXY file unchanged, none still being written, records that without rewriting the dataset (`CacheStore.confirm_dataset`): `snapshot_at` moves to when it started, `unsettled` to 0, and older caches gain their names, so a later non-TXY change (Finder's `.DS_Store`) doesn't rule out the quick check for good. Otherwise it lists, fingerprints and merges as usual. Shots cached or held that the folder no longer lists stop the load before any file is read (`shots_missing`): TXY files are written once, so another folder may sit at that path; a folder status check or details scan finds the same from the dataset's record alone (`cache_mismatch`, no data read). The folder's data is dropped from RAM and not shown (`FolderCache.mismatched`: session-only, up to 8192 folders, oldest dropped first; never a load's base) until a load completes or its cached data is cleared. The tab's line says Retry after checking the drive (remounting the right one is a fix) and offers Review…, which opens the window with that folder selected. One app-wide, non-modal `MissingShotsWindow` lists them (newest first; status-bar "⚠ N mismatched" reopens it) with Load as it is now (`FolderExplorer.load_as_it_is_now` → `allow_missing`, used once) / Don't load. When the session's count reaches 2, 4, 8…, loads and scans pause and none start (`IOService.mismatch_hold`, `MISMATCH_HELD`; browsing, cached reads, cache saves and icons go on) until Resume or Cancel all loads and scans; from 8, Skip mismatched folders lists them silently for the session with no more holds. Selecting a folder with saved counts and a disk cache does not list it (expanding still does). A failed check keeps the cached data with `Check failed` and Retry. A repaired TXY file gets a new name; right-click Retry / Refresh makes the folder's next check (at once for the shown folder) compare every file's size and mtime (`full_check`), since a file rewritten in place doesn't change the folder's mtime.
- **I/O trace:** Help › Record I/O trace (this session), off at every start and never saved, records every helper's source-folder operations as JSON lines in a new recording folder `<temp folder>/io-traces/io-trace-<date>-<time>/`, one `<pid>.jsonl` per helper (Windows' C runtime emulates O_APPEND, so helpers never share a file; `IOService.trace_dir`, sent with each request); refused when the temp folder is on a network or synced folder; one INFO line when it starts and one when it stops (also on quit); a status-bar note while on; Help › Show I/O trace folder; earlier recordings are kept unless the user picks Delete old traces when asked. Summarise with `.ai/sessions/2026-10-19-claude-smb-io-audit/trace_summary.py`, compare with `compare_traces.py`. Data-root verification is asked only by a listing's new mount table (one follow-up, never self-requeued, 5 s backstop); a load's fingerprint comes from its listing; RAM-held data without a disk cache gets a quick check (`memory_check`); selecting a RAM-held leaf folder doesn't list it.
- **Files still being written** (modified within `SETTLE_SECONDS` = 5 s, with an mtime ahead of this PC's clock (Tony, 2026-10-22), or changing while read) are never read or cached: they are left out of fingerprints and signatures (loads and scans alike), counted as `still being written`, and the cache records `unsettled` so the next check is a full one. Tests set `HELAB_SETTLE_SECONDS=0`.
- **Shot times** (DLD D7): a shot's time is its raw `d<N>.txt` file's mtime (Tony, 2026-10-20: raw files are never rewritten; a TXY's mtime is when it was converted). A load's, Live check's or Live save's own listing keeps the raw entries and stats one (reasons `load: shot time`, `live: shot time`, `save: shot time`; free on Windows, where the listing has the stat) only for a shot whose time isn't known: never for shots cached or held in RAM with a time (`FolderCache` sends held shots' times as `memory_raw_times` with `memory`, and as `held_raw_times` with Live's save), never in quick checks or cached reads. A known time is kept only while the shot's TXY fingerprint is unchanged (a run copied over the folder gets its own times), and a raw file modified within `SETTLE_SECONDS` gives no time yet (`io_ops.fingerprints._raw_mtime`). Raw files never enter fingerprints, signatures or reuse; a deleted raw file keeps the shot and its time. Without a raw time a shot's time is its TXY fingerprint's mtime, flagged (`DatasetView.shot_time` / `shot_times` / `fallback_times`).
- A helper occupies its slot **until its exit is confirmed** by the daemon reaper's in-memory exit flag — including cancelled/timed-out helpers and background cache writers. Never free a slot on message delivery or reader completion; duplicate exit notifications are matched by request identity.
- Browsing is two steps. `list` (one scandir, names only; the only stat is its own `.helab-root`'s, for data roots) gives counts and status at once, plus each subfolder's saved summary, history and cache flags from the local cache — so saved badges appear immediately and automatic visible scans don't redo them. `details` (the full scan) follows in the background for the signature and dates; subfolder dates come from the listing's entries (`_entry_stat(..., follow_symlinks=False)`: no call per subfolder on Windows). Saved status is a last-known result keyed by data root (root UUID and relative path; the SMB share is only a location) on disk, and by source path in session memory: a changed observed folder mtime adds the amber clock, and only that folder's own completed status check replaces its result. A status check or details scan that finds a folder's signature changed drops its datasets (`FolderCache._folder_changed`) but leaves its running load, Live check and cached read; only a clear (`_invalidate_data`) cancels them. Inodes and mount device numbers never invalidate saved status or scan-failure history. It is skipped while a load of a folder **without subfolders** runs — the load sends and saves the same folder summary. A listing writes only root-discovery records (`roots`, `root_volumes`, a nested root's re-key) and never clears a scan failure; a listing error records one. An empty `signature` means unknown, never "changed".
- Timeouts measure **time without progress**; helpers send heartbeats while listing or checking files. Listings, scans and a load's listing phase get one 60 s attempt with no retry (a timeout is one scan failure). Only a load's per-file reads retry, with 15/20/30 s attempts per file. Right-click Retry / Refresh and the status-line Retry list one folder with no timeout, showing elapsed time and a Cancel action; a load retry keeps its per-file timeouts. **A retry never runs beside the attempt it replaces** — it is held until that helper exits. Cancellation stops retries. Timed-out loads restart from completed RAM shots after fingerprint validation.

## Folder icons

**Folder icons:** The name column starts with a generic folder icon. Visible rows get native folder/volume icons (including macOS custom icons) from a separate `icons` helper in the shared background I/O lane, in batches of at most 64 with a 5-second no-progress timeout and cooperative pausing. `FolderCache` holds up to 4096 icons in session memory, shared across tabs; failed lookups retain the generic icon until Refresh. Icon lookup never runs during listing or model rendering. Refresh clears visible icons for another lookup. Keep the native Qt platform plugin in the helper; offscreen Qt cannot supply macOS custom icons.
