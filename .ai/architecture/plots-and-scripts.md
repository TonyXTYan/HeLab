## Script system

**Script system:** Analysis scripts live in `helab/scripts/`. Each script inherits from `HelabAnalysisScript` (`helab/scripts/base.py`) and implements `get_metadata()`, `get_actions()`, `execute_action()`. Scripts are discovered dynamically by `ScriptsManager` (`helab/scripts/scripts_manager.py`) via `importlib.util`, scanning a directory for `.py` files and grouping loaded scripts by their `ScriptMetadata.group`. The right-hand panel (`TreePanelWidget`, `helab/views/plots/script_tree.py`; the plot UI is the `helab/views/plots/` package: `dock`, `pictures`, `instance` (`AnalysisInstance`), `script_tree`, `settings_panel`, `workspace`, `arrangement`, `presets`, `cached_results`, `txy_source` (each plot's TXY row)) lists HeLab's bundled analyses in two groups, both imported (`MODULES`): **"Basic plots v1"** (`helab/scripts/standard/`, `group.py`: counts per shot, T/X/Y histograms, 3D scatter and transfer fractions in SI units, each drawn with any plotting library; modules `basic_plots`, `scatter_3d`, `transfer_fractions`) and **"DLD Front Panel Port"** (`helab/scripts/dld/`, `group.py`: the port of the lab's DLD front panel, below, with its own versions of those four, ids `helab.dld.*`, beside its other plots; modules `basic_plots`, `scatter_3d`, `transfer_fractions`, `correlations_plot`, `density_images`, `mean_position`, `release_time`, `shot_times`, `shot_trends`, `t_spectrum`, `velocity_distributions`; Tony, 2026-10-20: the port's plots sit beside Basic plots v1, which stays as it was), and any folder loaded with Load Scripts…; `helab/scripts/legacy_plotly/` holds older lab Plotly figures.

**Live scripts** (v0.0.8; `agent/live-scripts`, `5eb4225`, `63b0baf`, review fixes `a18e4c9`, `c79f210`, landed `971f4af`; [design](../sessions/2026-11-02-claude-live-scripts/design.md)): the folders loaded with Load Scripts… are remembered (`script_folders`, [settings](settings.md)) and loaded again at start (`TreePanelWidget.restore_folders`, `RESTORE_DELAY_MS` 200 after the event loop starts, so after the window shows; `PlotReopen.restore` waits for `foldersRestored`, and `record` keeps last time's record meanwhile). Not at start: a folder on a network share (`on_network`, from the mount table only; never watched either), and none when `<app folder>/scripts-loading.json` is there (written before each folder load, removed after: a load that never ended); those wait for Reload, said in one amber line (`scripts_start_note`; amber by its palette, set once at construction, not a style sheet, so polishing the panel runs no Python code: a style sheet sent a PaletteChange to `ElidedLabel.changeEvent`, and a test's dropped panel collected there crashed its worker, `823589a`; [testing](testing.md)), and stay remembered. A start drops a marker naming no remembered folder, and skips one start for an unreadable marker and drops it; a deliberate Reload (button or a folder's menu) or Load Scripts… ends a marker it didn't make, auto-reload doesn't (`reload_scripts(…, deliberate=False)`). The Scripts row is `Group [▾]  [Load Scripts… ▾]  [Reload]`: Load Scripts… is a menu button (same ID `load_scripts`) listing "Script folders", each with Reload / Remove from the list (`script_folder_reload`, `script_folder_remove`; a missing folder says "folder not found"), then "Reload when a script is saved" (`script_auto_reload`, off; only then a `QFileSystemWatcher` watches the script folders, their `.py` files and their helper files and folders, re-adding paths after each change; a 0.75 s settle, then a folder reloads only when a stamp (path, size, mtime_ns) changed; a new helper not modified since the load is stamped, not a change). `ScriptsManager` (Qt-free) keeps each user folder on `sys.path` (appended, so HeLab's and installed modules keep their names) while loaded; its **helper modules** are the `sys.modules` entries with a file inside it (never `helab.*`, the stdlib or site-packages), unloaded on each reload so they import fresh, lazy imports in `compute` included once seen (`_know_helpers`); user folders import from source only (`_SourceOnlyLoader`, a `sys.path_hooks` entry limited to the user's folders and refusing installed packages, `_PROTECTED`: no `__pycache__` read or written, since a `.pyc` is checked by whole-second mtime and size, so HeLab writes nothing into them); a file without scripts that the folder imports is a helper, not a failure; a folder's scripts record their file's hash folded with its helpers' `relpath:hash` (D1; bundled analyses keep the plain hash). Failures are kept (`errors()`: `LoadError(path, message, details)`) and listed at the Scripts tree's end whatever the group, "⚠ N script files didn't load", one line per file, the traceback in the tooltip and, on a double-click, a non-modal details window (`script_error_details`). **Reload** (`reload_scripts`, ID `reload_scripts`, its own slot `_reload_clicked`) holds the folders' plots (runs cancelled, nothing submitted, Live revisions wait) and waits, reading "Reload (waiting)", until no run of their scripts is queued or computing (`AnalysisRunner.in_flight` / `AnalysisQueue.in_flight`: a reload never runs under a `compute`); then each plot takes the new code in place (`AnalysisInstance.adopt_script`: `saved_plot()` captured, script, policy and constant keys swapped, the settings page rebuilt in the same widget (`_fill_page`), settings re-applied through `check_plot` with the new file hash, rerun drawn anew; a removed, retyped or new parameter is named in the Presets row, "Reloaded · ⚠ 3 settings at the script's defaults: …") or keeps its old code and last result with an amber line ("⚠ Script didn't reload (…): still running the code loaded at 14:02"; `keep_script`: Rerun and Live go on with it; the next good reload adopts). A plot waiting on its own TXY choice doesn't run on a reload (`_own_waits`). Loading an already loaded folder again is a reload. Bundled analyses are never reloaded. Wording: Q49.1; the real import stays on the GUI thread, after a try-import (below, Q49.3 (b)).

**The try-import** (Q49.3 (b); `fdd895c`, review fixes `56f594b`, Follow-ups, landed `72ab47a`; [design](../sessions/2026-11-03-claude-followups/design.md)): before each import of a user script folder (at start, `restore_folders`; on Reload, a folder's Reload and auto-reload, `_try_reload`; on Load Scripts…, now through `reload_scripts([folder])`), `_probe_then` test-imports it in a separate process, and the real import follows only when that answers. **The probe** (`helab/scripts/probe.py`, Qt-free at import, in `PURE`): `main([FOLDER, RESPONSE])` makes an offscreen `QApplication` (`QT_QPA_PLATFORM=offscreen`, program name "HeLab script probe") when a `*qoffscreen*` plugin is in Qt's plugin folders (a missing one would abort the process), else none, said in the log; it writes `{"kind": "ready", "application": …, "pid": …}`, runs `ScriptsManager().add_folder(folder)`, writes `{"kind": "done", "loaded": …, "seconds": …}` (each line fsynced) and ends with `os._exit(0)`, keeping its QApplication referenced (`_KEPT`) until then, since deleting it would wait for Qt's global thread pool (review FU-1). `probe.command`: `[sys.executable, "-P", "-m", "helab.scripts.probe", …]` from source, `[sys.executable, "--helab-script-probe", …]` frozen ([release-and-ci](release-and-ci.md#building)). A file that raises or calls `sys.exit` at import is that file's error, as in the GUI, not a probe failure; only a hang or a crash skips the folder. **The GUI side** (`script_tree.FolderProbes`, a `QObject`): one `QProcess` per folder, at most `PROBES_AT_ONCE` (2), the package root on `PYTHONPATH`, stdout and stderr to files in a private `helab_probe_*` temp folder, stdin an open pipe never written (so `input()` at import waits and meets the limit); a 100 ms timer (`PROBE_POLL_MS`) reads the response file only while probes run; no `waitFor*`. Limits: `PROBE_SECONDS` (10 s, from `ready`; Q58.2), `PROBE_START_SECONDS` (60 s to get ready), and `PROBE_EXIT_SECONDS` (5 s after `done`: a probe still running then is killed with a warning and its folder passes). A probe over its limit is killed; its answer comes on `finished`, so a probe holds its folder until its exit is confirmed. `FailedToStart` passes the folder with a warning (it imports anyway). The reasons (Q58.1): `its import didn't finish within 10 s`, `HeLab's test import didn't start within 60 s`, `its import stopped HeLab's test import (exit code N)`, `its import crashed HeLab's test import`, with the stderr tail (read from the file's end) in the details. **Rounds:** one at a time (`_probing`), the button "Reload (checking)" with the tooltip "Test-importing N script folders in a separate process first"; a reload asked meanwhile waits in `_pending` for its own round. When a round answers, its import waits (`_end_round`, the answers kept: no second round) until no run of its folders' scripts is queued or computing, on any runner, reading "Reload (waiting)"; those plots are held meanwhile, and each runner's `finished` is connected before runs are counted (`_listen`; Reload during that wait counts again). A plot opened while its folder is in a round or waits to reload is held from its start (`_hold_if_reloading`, in `run_analysis` and `reopen_plot`) and takes the new code with the others (`_adopt`); if the folder keeps its code (a failed test import, the class gone, the folder removed), `keep_script` runs it on that code. A reload asked meanwhile holds its plots again before its own round (C-4, C4-1, C4-2, PR #11's second Codex review; landed `82ce6dd`). A folder that fails at start joins `_skipped` (the start note, its tooltip adding `PROBED_NOTE`); later, `ScriptsManager.skip_folder` lists it as `<folder>: didn't load: <reason>` (`PROBED_NOTE` and the stderr tail in the tooltip and details), its scripts leave the panel, its plots keep their old code (`keep_script`), and it is stamped so the next save tests it again. A folder removed from the list while tested is dropped. `stop()` on `aboutToQuit` kills running probes without waiting and drops queued ones. Bundled analyses are never probed. **The loading marker stays** as the backstop for what the probe can't catch (a file changed between the test and the import, code that acts differently in the GUI process, a probe that couldn't start). Top-level code of a user script runs twice, once in the probe; the manual's script page says so. Tests turn it off with the module flag `PROBING` ([testing](testing.md)).

**The loader's module name** (`c8d400c`, Docs floor, landed `b0e3aac`): a user script's module is in `sys.modules` as `helab.scripts.dynamic.<file name>` only while its file runs (`scripts_manager._importing`, around `exec_module`); afterwards whatever held the name is put back (or the name popped), on success and failure alike, so nothing is left in `sys.modules` (`test_scripts_folder.py`'s invariant). This lets a script with `from __future__ import annotations` and a `@dataclass` load. An overlapping load of one name is refused (`_IMPORTING`), not waited for. `typing.get_type_hints` can't resolve a script class's string annotations after the load.

**The API reference for script writers** (A54.1, A54.2; landed `b0e3aac`): the manual's `docs/reference/api/` pages render, with mkdocstrings, the modules `ruff.toml` lists (`helab/scripts/base.py`; `helab/analysis/` `dataset_view`, `parameters`, `selection`, `fits`, `profiles`, `results`), whose public names ruff's D1 keeps documented (Google style). A module added to the reference is added to `ruff.toml`. `dataset-view.md` names its classes one by one, leaving the module docstring out until it is public-safe (A56.2). Docstrings are public text: no person's name, internal ID or `.ai/`/`roadmaps/` path.

## Dataset analyses

Dataset analyses subclass `DatasetAnalysis` and get an `AnalysisContext` (`helab/analysis/results.py`, with `AnalysisResult`, its `Coverage` and `RamResults`): an immutable `DatasetView` (`helab/analysis/dataset_view.py`: identity = source path, `root://` key and signature, and its chain (`ViewIdentity.chain`, `build_view`'s token, kept by `with_shots`: the signature is the folder's MATLAB TXY's, the same for every load and TXY choice of it and `sha256("[]")` without MATLAB TXY, so a fresh load, another TXY choice or profile is another identity, never an earlier revision; plots-1); a revision that `with_shots()` advances; shared arrays made read-only down their `.base` chain and handed out as views, never copied; its identity also names its TXY source, `source`, "" for the default, and each HeLab shot's origin, `origins`; results record their covered shots' origins and, for another source, `txy_source` in the reuse key; `DatasetView.on_read` names the shots converted on read and keeps them through revisions (caching v2 stage 3, `0cd133f`; `describe` says "…, converted from raw"); each plot's settings have a TXY row, with Keep (A47.5), [converter](converter.md)) and the effective parameters, never the tab. `compute` runs in the analysis worker thread (`helab/analysis/runner.py`: `AnalysisRunner`, whose signals wrap the Qt-free `AnalysisQueue` in `runner_core.py`; FIFO, cooperative cancellation), `render` on the GUI thread. The script contract and the Qt-free analysis modules import no Qt, plotting library or `helab.utils.constants` (which imports Qt); `tests/test_headless_imports.py` lists each `helab/analysis/` module as Qt-free (`PURE`, with `helab.utils.ram_buffers`) or Qt (`QT`: the runner, the budget, the Live feed and the drawing modules). Each declares `analysis_id` and `version`, and the manager records the file's SHA-256 (`AnalysisIdentity`, `helab/analysis/identity.py`). A script hook that raises while its plot opens (`live_policy`, `constant_keys`, `parameters`, `backends`, `minimum_size`) is logged and shown as "<name> failed: …" (status bar or dock); HeLab goes on.

## Parameters

Parameters are `ParameterSpec`s (`helab/analysis/parameters.py`: float, int, bool or choice, in tree groups, optionally shown only under one choice, SI-prefixed units, and a `page`: more than one page gives the plot's settings a tab each); the plots share Shots (From shot N first, then all / last N / up to a shot, by shot number so gaps are skipped; the dock says why none are chosen: From shot past the last, or To below From) and View range (auto-crop keep % or manual T/X/Y; a reversed axis uses its full extent and says so) from `helab/analysis/selection.py` (auto-crop, display sampling and histograms: `helab/analysis/stats.py`), and every DLD port event plot but Release time has a Mask group (below).

## Results

Results stay in RAM (`RamResults`, R1; a released plot's result keeps its record without data, `RamResults.released`).

## Presets and reopening

Presets (`roadmaps/presets-and-workspaces.md`, stage 1): a plot's settings page has a Presets row (`helab/views/plots/presets.py`, `PresetBar`): script presets saved per analysis id and action, shared by its plots, holding every parameter and the library (not the Live group) and the plot's TXY choice (`TxyChoice`: source, profile name and tag; A47.5, `63817b5`, landed `971f4af`), unless the TXY row's **Keep** box ("Keep this plot's TXY choice", ID `txy_keep`, on by default) is off; after Apply or Save, each setting that differs from that preset has a dot (the highlight colour, not amber) and the row offers **Save N changes ▾** (Save to preset “p”, after asking, or Save as new preset…). The **Presets** menu saves one folder's arrangement (the folder, Live, its plots with their own settings, library, Live group and places, its TXY choice and Keep; a script preset's name only as provenance; `ArrangementPresets`) and applies it after asking Replace / Add / Cancel (Add opens its plots beside the open ones, without the saved dock layout; a preset that can't be read is a modal "Preset can't be read" through the module function `presets.warning_box`, which `ArrangementPresets._warn` calls bare in its own module, so conftest's autouse `no_modal_warnings` fails a test that would wait on it, `566eed6`): the tab opens the folder as typing its path would and loads it deliberately once it's known to hold data, the plots open in place waiting for its data, and Live starts once the data shows (`PresetFolder`, under `start_live`'s rules) or says why. The plots open at quit reopen at start (Settings → General, "Reopen plots at start", default on; `helab/views/plots/arrangement.py`, `PlotReopen`): recorded on plot open, close and quit, each running on its folder's data from RAM or one local `cached` read only (`FolderWait`), else waiting for a tab's load; `AnalysisInstance.run_reopened` is the one place a reopened plot decides to run. Plots that couldn't reopen get one non-modal question per start: Keep for later (the default; they reopen at a start where their script is loaded) or Drop. Records and validation are Qt-free (`helab/analysis/presets.py`: one `Arrangement` format for both, `check_plot` names every saved value that doesn't fit: unknown key, type, limit, removed choice, missing parameter, library, version; never clamped or replaced). A saved TXY choice (`SavedPlot.txy`, `txy_keep`, `ScriptPreset.txy`; optional JSON fields, `FORMAT` stays 1) is checked like a setting (`check_txy`, `check_plot(…, profiles=)`: a renamed profile is found by its tag, with a note; an unknown profile or source is named and the plot stays as the folder's tab; the presets inspector checks without profiles, A49.3). A reopened plot with its own choice takes it while waiting and loads it once its data is found only if HeLab read the folder this session (listed, or loaded or checked), else it says "Select <folder>, or Rerun, to load HeLab's only (…)" and waits for a tab's load of the folder or Rerun, so reopening never reads a folder by itself (D4); a reload of its script (auto-reload too) doesn't count as a read either. A script preset without a choice leaves a plot's choice as it is (D2); Apply of one with a choice switches to it; records without one restore as the folder's tab. Settings → Cache › Presets… (`helab/views/PresetsInspector.py`) lists every preset with whether it fits the installed script, and renames, duplicates and deletes them, naming a change refused or kept in RAM only; a script with no parameters shows its reopen note on its status line; an arrangement preset's Live waits for its folder's first load to show, and offline a folder never listed is named (C-23, C-29, C-30); values are edited by applying a preset, changing it and Save to preset (editing in the inspector is not built).

## Following Live, coverage and plot display

A plot follows Live by default (its settings' Live group: Follow Live, Rerun every N new shots, Wait after a run, from the script's `live_policy`; not parameters): a run is never cancelled for new data, one pending revision per plot (newest wins), a failed rerun keeps the last plot with an amber line, Follow Live off pins the revision. Every result records its coverage (shots used and fingerprints, `covered_shots`) and `reuse_key()` (JSON). Plots with nothing to draw say why (`helab/analysis/empty.py`). Plot titles are `WrapLabel`s (`helab/analysis/plot_text.py`): they wrap to the width the layout gives them, so every DLD port plot fits a 560 px dock; one note per line, and from a "⚠" on, amber (`AMBER`, `helab/utils/colours.py`, the app's one amber). Every bundled PyQtGraph plot updates in place on a rerun (`DatasetAnalysis.update`), keeping zoom and pan, unless what its items are changes (e.g. log Y, the fits). Each plot has a least size by design, never a user setting (`DatasetAnalysis.minimum_size`, default `PLOT_MINIMUM_SIZE` 200×200 logical px; Basic plots v1's transfer fractions 240×360, T/X/Y histograms 240×400), held by its dock's plot area with the source lines (`AnalysisDock.set_minimum_plot_size`). Each plot dock's source is two lines, the input and the settings in short form (`DatasetAnalysis.describe_run`; e.g. `Data source: <run> · rev N · shots … · <id> vX` / `last 10 shots · auto-crop 99 % · bins auto`), with the full record in the tooltip. The first line starts "Data source" while the tab shows the data the plot ran on (by shots, fingerprints and origins, `DatasetView.held` / `held_of`, memory only; by shot numbers for a plot with its own TXY choice), else "Showing previously loaded data"; a plot following Live is always the former (plots-1).

## Transfer fractions

**Transfer fractions** (`transfer_fractions.py` in each group: Basic plots v1 in s, every library, newest-shot highlight, its order detection and counting in `helab/analysis/orders.py` (pure NumPy/SciPy, using `peaks.py`'s `half_maximum_width` and `refine`); the DLD port's in ms with a Mask, the same highlight and the same detection (`orders.detect`, Reference spacing in ms), updated in place; ported from `monitor_momentum.m`/`fraction_calc.m` in `legacy/Momentum_Bells_test`) finds order 0 (the tallest peak in Search T, each end 0 = open) and the spacing in the T histogram (in both groups, order ±k is the most prominent clear peak within 30 % of a spacing from k spacings out, starting from Reference spacing, default 15 ms as in `fraction_calc`'s windows, so a bump between orders isn't one), and plots each order's share per shot (over the orders' sum; half-open windows, a Window ± over half the spacing clipped to it). Its T histogram can highlight the newest chosen shot (T histogram › Highlight the newest shot, as in the T/X/Y histograms: drawn to the histogram's total, its real counts on a right axis, `helab/analysis/overlay.py`; shown even when Minimum counts left it out, and says so). Its order 0 checks catch comparable peaks (another order with ≥ half its events: "⚠ order 0 unsure") and jumps between runs (a whole number of orders from the last detection, which the hidden centre then keeps: "⚠ order 0 moved"). A Search T with both ends set is the user's word on order 0: no warning for orders outside it, and a last detection outside it is replaced (a plain line says so). A first run with a transfer over about 2/3 can still take +1 for order 0. `tests/test_transfer_fractions_matlab.py` checks the counts against a Python `fraction_calc` and lists the intended differences, among them no X/Y rotation (MATLAB rotates by `dld_xy_rot` 0.61 rad; Tony 2026-10-20: not in HeLab). A script's `detected_parameters` fills its settings from a run (here the manual centre and spacing), except a setting changed since the run started. The centre hint shows only while no plot dock is open.

## The Settings panel and floating plots

One Settings panel (top right, `PlotSettingsPanel`) shows the active plot's settings: the plot last clicked, focused or brought to the front among tabbed docks, floating ones included. It follows Qt's focus, active-window, tab and plot-visibility signals (no event filter; plot docks take click focus); showing a plot moves focus left in another plot to it, and when the shown plot is hidden or closed, the most recently shown visible plot shows. Closing the main window closes its plots (`PlotWorkspace.close_plots`). The plot area is `PlotWorkspace` (`helab/views/plots/workspace.py`, the window's `plots`): the docks' main window and hint, the open docks, the Settings panel, the Live feed, the RAM budget with its status-bar button and window, and how a dock shows its result and source lines; plots and the Scripts panel take it, never the main window, and it asks the window only through callables (current tab, tabs, notices, Settings, closing). Its chooser names the plot and raises another, and each plot's page keeps its edits. A new plot is tabbed with the shown plot if docked, else the newest docked one (never a floating or lone hidden one; `TreePanelWidget.tab_target`); tab × buttons find their dock by identity (`DockTabCloser`). A floating plot's page moves into its window (`AnalysisDock.settings`, right of the plot, the same editors: edits and Rerun go with it) and back when it docks again; while the shown plot floats, the panel says "Settings are in this plot's window" with Show plot window, which raises it with its settings open. A plot being dragged keeps its page until it is let go (`DragEnd`: a filter on that dock only, during the drag; the only event filter in the Settings panel). Floated other than by a drag (the title's float button, a double-click on the title: `AnalysisDock.event` notes the `MouseButtonDblClick`, since the float comes on the press), a plot opens at 800×600, 40 px right of and below the visible plot floated last (the first: of its docked place), kept on its screen's available area (`AnalysisDock.place_floating`, Q33.3); a drag leaves it where it is let go. A restart puts floating plots back where the user left them: the arrangement record keeps each plot's `floating` flag and the plot area's `saveState`, restored after the plots open. A floating plot's settings section starts with a Dock button (`FloatingSettings.dock_button`: "⇲" closed, "⇲ Dock" open; accessible name "Dock plot", ID `plot_dock`; Q33.4). The Float button beside the Settings panel is Qt's, on the docked plot's title (A33.4, Q36.1): whenever the main window is active while the shown plot floats (and right after a float if it stays active), the panel shows the most recently shown plot still docked and on screen, so that button acts on the plot the panel names; the floating window shows its own settings, and activating it names it again; with none docked, the panel says "Settings are in <plot>'s window" (`PlotSettingsPanel._window_activated`). The section starts closed as a strip (▸, the plot's name and settings summary); open, its splitter sets its width; opening and closing widen and narrow the window so the plot keeps its size; open/closed and width last the session per plot. `AnalysisDock`'s `widget()`/`setWidget()` are the plot, inside a splitter frame. Typed numbers in settings (`UnitSpinBox`, in `helab/analysis/parameter_tree.py`, which builds a plot's pyqtgraph settings tree from its `ParameterSpec`s): a bare number is in the unit shown, a prefix alone applies, "." or the locale's comma, and beyond the limits the nearest limit; in a box with a fixed prefix (`fixedPrefix`: the DLD port's T/X/Y settings in ms or mm, `range_specs(…, fixed=True)`) "," only groups thousands and "." is the decimal point, whatever the locale ("20,450.5" is read, "20,5" refused). Plot settings trees are `SettingsTree` (the same module), whose name column takes at most `NAME_SHARE` (half) of the tree's width, each name in its row's tooltip, so values stay in view in a narrow panel (`42a82b0`, the v0.0.7 Mac smoke pass). The RHI surface (a hidden QQuickWidget that keeps the window from closing and reopening when the first web view opens) is made only on macOS's own windows (`HelabMainWindow.needs_rhi_surface`), never offscreen. Unmaintained plotting-library prototypes are in `dev/plotting-prototypes/`, outside the package. A Plotly pane's figure leaves the Dash server as its plot closes or is replaced: `PlotlyPane.release_figure()` runs its `weakref.finalize` (once; `dock.release_figures(widget)` from `AnalysisDock.setWidget` and the plot's close), and the finalizer covers a pane dropped otherwise. Nothing connects Python to a pane's `destroyed` (a lambda there crashed with SIGSEGV when Qt deleted the dock; AGENTS.md's rule, `tests/test_destroyed_connections.py`).

## Visualization

**Visualization:** Plotly is used for interactive 3D scatter; Matplotlib for publication-quality output. PyQtGraph draws the 2D analysis plots by default (counts per shot, the T/X/Y histograms and, in the DLD port, their fits, density images with a colour bar, mean position, T spectrum, shot times and trends on a date or shot axis, release time, velocity distributions): fast redraws for Live, and it paints on lab PCs that can't paint QtWebEngine. Every "Basic plots v1" plot can be drawn with any of the three (Drawing › Library in its settings, `helab/analysis/backends.py`: a script's `backends()` names them, default first (the DLD port's plots name none: one library, no Drawing group), and `draw(result, backend)` draws one; not a parameter, so switching redraws the shown result without a rerun and the record says "Drawn with …"). Defaults: PyQtGraph for 2D, Plotly for the 3D scatter. Basic plots v1's PyQtGraph titles are `WrappingLabel`s (`backends.set_title` for a plot's own; the DLD port's are `plot_text.WrapLabel`s): they wrap to the plot's width, since PyQtGraph's own label holds the layout at its text's full width and runs the plot off the widget's edge. Matplotlib uses `matplotlib.figure.Figure` (never `pyplot`) in `MatplotlibPane` (`helab/analysis/backends.py`) with its toolbar. Reruns (Live's next shots) update every plot in place in every library (`update`), keeping the user's zoom and pan, else following the new data: Plotly swaps the page's figure (constant `uirevision`); PyQtGraph sets new data on the same items (auto range stays off once zoomed; drawn anew when the layout changes: log Y, the highlight or its colour, the number of orders); Matplotlib redraws onto the same figure (`MatplotlibPane.redraw`: zoomed axes keep their limits, 3D keeps its rotation, Home goes to the new data's limits, twin axes marked `FOLLOWER`); PyQtGraph's 3D view needs OpenGL (`opengl_available`, never offscreen) and otherwise says to pick another library. The 3D scatter is Plotly via the Dash server, with Open in browser (`PlotlyPane`, `helab/analysis/panes.py`); `DashServer.remove_plot` runs when a plot closes. The 3D scatter's page updates in place (`DashServer.update_plot`: one atomic per-plot snapshot, a 1 s poll per page, constant `layout.uirevision`), keeping the camera across reruns, in the dock and in browser tabs; a closed plot's page says so and stops polling. `DatasetAnalysis.update` lets a plot update in place. The scatter and the histograms can highlight the newest shot (`selection.newest_specs`; the histograms read its real counts on a right axis in its colour). A log axis takes `PlotDataItem`s (pen None for points): `ScatterPlotItem` ignores log mode. Avoid PyVista/VisPy (known data-point issues with large files). `helab/utils/dash_server.py` runs a background-thread Dash server (`127.0.0.1:8050` preferred; another free port when it's in use, or held on all addresses by another program, which macOS and Windows would otherwise let HeLab share: `DashServer._listened_on_all`, plots-4; Windows beside a dual-stack `[::]` listener is a known issue) to serve interactive Plotly figures in a browser tab via `/plot/<id>` routes.
