## Logging

Each HeLab logs to its own `<app folder>/logs/helab-<pid>.log` (INFO and up, rotated at 1 MB, 10 older files; macOS `~/Library/Caches/HeLab/logs/`, Windows `%LOCALAPPDATA%\HeLab\logs\`; Help › Show log folder). An unhandled exception, on any thread, is logged with its traceback and HeLab carries on, with a status-bar note "Unexpected error, logged: …"; the same one is logged at most once a minute, its repeats counted (`helab/utils/app_log.py`, started first in `main()`). A source file dated more than 2 s ahead of this PC's clock makes helpers send `clock_skew`: HeLab says the computers' clocks are out of sync, once per share or volume per session (`ClockSkewWarning`), and Live on that folder stops like an error stop. At startup, off the GUI thread (`helab/views/OldLogs.py`), HeLab deletes the oldest log files by mtime beyond Settings → General → Log files to keep (default 300, every session's files and rotated copies counted); past 50 MB left it asks once per session "Log files use X MB. Delete old ones?" (Keep the default, for the session; Delete goes under 20 MB). Never a running HeLab's files (live instance locks, this pid) or one modified in the last minute; one that can't be deleted is skipped and logged (`app_log.tidy_logs`, `trim_logs`). **Milestones** (`agent/runner-tools`, landed `0316bae`): when a folder's load, a plot's compute or a conversion ends, HeLab logs one INFO line on `helab.milestone`, `MILESTONE <event> key=value …` (`app_log.milestone` writes every one, `parse_milestone` reads it back): `load_done` (`folder shots events seconds source=cache|folder|check|save live`, from `FolderCache`), `plot_done` (`script version action plot job seconds state=ok|failed|cancelled`, from `AnalysisRunner`), `convert_done` (`folder by=live|cli converted no_hit unconvertible waiting kept output seconds`, Live auto-convert and `helab convert`; not for a run that changed nothing). `no_hit` differs slightly: Live counts the growth of its no-hit set (a failed run's no-hit shots carry into its next line), `helab convert` counts every no-hit conversion of that run (a stale shot converted again included). A runner (the smoke pass) waits on them in the log file; the only path in them is the folder.

## Threading

**Threading:** The GUI process has no worker pools, except the single analysis worker thread (`AnalysisRunner`), which computes analyses and never does source I/O, and the short-lived startup thread that tidies old log files (`OldLogs`). Source-folder and disk-cache work runs in isolated `io_helper` processes, whose results daemon reader threads deliver (see Responsive filesystem I/O). `GUIWatchdog` and the Dash server run on their own background threads, and `io_service.py` starts short daemon threads (`HeLab-artifact-cleanup`, `HeLab-cancel`).

## Window resizing

**Window resizing:** Keep Qt's normal main-window resize and repaint handling. Disabling updates for the whole window during resize and restoring them with a timer can stop paint delivery while I/O continues. Resize regressions in `tests/test_window_resize.py` check continuing paint events and scan cancellation, not just `updatesEnabled()`.

## `FolderCache` memory and the RAM budget

The active browser additionally uses session-only `FolderCache` (`helab/utils/folder_cache.py`), shared by models using the same IOService. Completed directory snapshots have a 10-second freshness window; explicit refresh bypasses it. Shared scan/load/resolve jobs have per-tab subscriptions, so closing one tab does not cancel another's work. Datasets share read-only NumPy arrays with private dictionaries per tab; analysis code that intentionally modifies an array must call `.copy()`. The RAM budget (Settings → Cache, steps of 1/128 of RAM, default 1/8; `FolderCache.set_ram_budget`) evicts datasets no tab shows, least recently used first, while open tabs pin their current datasets. Plots count too (`helab/analysis/budget.py`, `RamBudget`; its Qt-free parts, the shares, `hollow` and `restore`, in `budget_core.py`): each plot's view, its result arrays (every result `RamResults` keeps for it) and a released plot's PNG picture, by buffer (`helab/utils/ram_buffers.py`), so arrays shared with a held dataset or another plot count once (`FolderCache.plot_bytes`); eviction keeps a dataset whose arrays plots hold anyway. From 50 % of the budget the status bar shows it; at 75 % a non-modal window lists the biggest plots and folders (once per crossing, re-armed below 70 %); above 80 % datasets no tab shows go first (`evict_to`, again after each release), then plots are released, least recently shown first (one reloaded in the last 10 s last), in two passes (first only plots that free more than their picture with every other plot staying), until under 80 % (never the shown, a running or a Live-following plot; none closed). A released plot shows its PNG picture with Reload and keeps a hollow view (its shots' numbers and fingerprints); it reloads from RAM or a local `cached` read only, never its folder, exactly the shots it drew by fingerprint, naming changed or missing ones, when it becomes the shown plot (Settings → Cache, `plot_auto_reload`, default on; not again after finding nothing until its folder's data or disk cache changes) or on Reload. Directory snapshots are bounded to 256 folders and 100,000 retained entries. This memory store supplements the compressed disk cache and **never reads disk during rendering**.

## UI

**UI:** Model-View pattern. The active `FolderExplorer` uses `SnapshotFileSystemModel` (`helab/models/SnapshotFileSystemModel.py`), a `QAbstractItemModel` that only reads memory during rendering — badges, tooltips, summaries and relative ages must never touch the source filesystem, the disk cache, or submit I/O. Directory contents are scanned on selection or expansion; an unlisted folder whose saved summary has no subfolders (`has_dirs`) shows no expand arrow until selecting it (or a load's listing) finds some; automatic basic scanning of visible folders is off by default and never rescans folders with saved results. Freshness indicators are hints only and never schedule scans or loads. Navigation and direct path entry stay available during I/O. A folder's status as the browser shows it is a `StatusReport` (`helab/models/StatusReport.py`, plain data); freshness hints come from `helab/utils/cache_freshness.py`, and shared labels from `number_format.py` (byte sizes by kind and OS, Q26.1; the status bar's RAM in GiB), `time_format.py` and `helab/views/explorer_text.py`, all memory only. The folder summary panel, cache-freshness icons and their wording are described in `.ai/memory/results/folder-summary-indicators.md`. The main window (`helab/views/HelabMainWindow.py`; folder tabs in `FolderTabWidget.py`, the Settings window and its tabs in `SettingsDialog.py`) uses dockable panels: left tree view with **Folder details** (`helab/views/FolderDetailsPanel.py`) below it, right properties panel, center plot area. Quit: `closeEvent` → `_wait_for_saves` (Live off, the converted TXY's last-uses flush, the quit window listing every pending operation; [live](live.md)), then `quit_watch` ends the process within 1 s.

**Accessible names, IDs and the runner's Debug items** (`agent/smoke-ready`, landed `4ad8ac5`; [smoke automation](../../roadmaps/smoke-automation.md)): every interactive control gets an accessible name, a one-line static description and a stable ID (`objectName` and accessible identifier, which Qt 6.11 gives as macOS AXIdentifier and Windows AutomationId) through `helab/utils/accessible.py` (`identify`), where the control is created. IDs are unique among a window's shown controls, never built from text: per-item IDs come from the script's analysis ID, the plot's number or the folder tab's number (a folder tab's own controls keep the same IDs in every tab, Q34.2). On macOS and Linux Qt names a combo box by its current choice, so a runner finds combos by ID. A plot parameter's editor exists for accessibility only while its row is selected (pyqtgraph hides it); Return or Enter commits and closes it, Escape cancels (`helab/analysis/parameter_tree.py`). Qt's tab bar never exposes a tab's close button to accessibility (only the tabs and scroll arrows), so a runner closes tabs from the Debug menu. The **Debug menu** holds the runner's items, filled from memory as they show and each calling its control's own code path: Run Plot, Script Group, Show/Close Plot Tab, Show/Close Folder Tab, Settings Tab, Save Window Screenshot… (a picked PNG), Save Window Screenshot to Temp Folder (no dialog: `<temp>/screenshots/helab-<window>-<time>.png`, logged and named in the status bar, Q34.1), Screenshot of › each visible HeLab window, and Dump State… (`helab/views/state_dump.py`: JSON of what the window shows, from memory only, schema `helab.state/1`, the `--smoke` channel's future state answer). Screenshots grab the HeLab window in front when the menu opened (`QWidget.grab`); QtWebEngine panes that paint black on screen (the lab PCs) are black in the grab too. `helab --geometry WxH+X+Y` opens the window there for that run only. Folder details shows the current tab's selected folder, its load (state, progress, files, elapsed time and time left, rate) and the loaded dataset, plus the tab's and app-wide I/O activity (State names the file being read and Files what is left; All I/O names a single running load's folder and a click shows it in its tab, and its tooltip lists each running helper with its tab, progress, file and time, `IOService.request_note`); the plot area keeps only a one-line hint (`CentralHint`, room for later tips). The status bar is short: this tab's main activity (`FolderExplorer.activity_brief`) │ app-wide counts (`IOService.activity_counts`); full wording is in its tooltip and Folder details. A load's running time and estimate come from `LoadClock` (`helab/utils/load_clock.py`) on the shared job: queued and paused time are excluded, and the rate counts only TXY files actually read (`read_bytes`/`read_files`/`total_read_bytes` in the helper's progress events), and a read with no progress for 5 s shows "no progress for M:SS" instead of an estimate. Small widgets: `ElidedLabel` (`helab/views/ElidedLabel.py`, a one-line label that elides to its width, for the status rows) and `HoverMenuToolButton` (`helab/views/HoverMenuToolButton.py`, a toolbar button whose menu also opens on hover); the Debug menu's Show all Icons and Show Memory Usage open `DebugIconsWindow` and `MemoryUsageWindow` (`helab/views/`).
